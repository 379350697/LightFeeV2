### Scope

This pass covers only production issues 3-11. Issues 1-2, including Aster
private truth/signature behavior, are explicitly excluded from this cluster.
No production connection, deploy, manual order, cancel, or runtime-state edit is
claimed here.

### Summary

The existing local code already had broad entry-admission, pending hedge,
pending-close, shared order-submit uncertainty, OKX amend fallback, recovery
ledger, and snapshot degraded coverage. This pass did not duplicate those
existing fixes. It closed the remaining evidence gaps that blocked deterministic
post-deploy classification:

- recovery live-mismatch flatten success/failure now journals the cleanup intent
  id, owner resolution, core truth owner, probe family, and post-cleanup
  read-only position truth.
- pending-entry passive maker rest-timeout cancel now records that REST cancel
  acknowledgement is not terminal and that progress/order truth remains the
  next authority.
- structural perp open-interest degraded diagnostics now include endpoint,
  source, floor/current value, fallback source, and targeted revalidate scope.

The behavioral boundary is unchanged: order submission, cancellation,
recovery cleanup, passive close, and snapshot gating decisions still use the
existing state machines.

### Root Cause

This cluster is not a single missing branch. The root issue was that several
already-fixed V1/exchange-semantics paths still lacked deterministic evidence
for deployment review:

1. live mismatch flatten could succeed or fail without enough post-cleanup truth
   to prove whether the exchange artifact was actually gone.
2. passive maker timeout cancel evidence did not explicitly say that ACK is not
   terminal and reconciliation must continue through order/progress truth.
3. open-interest structural degraded diagnostics had the decision but not enough
   venue/source/floor/current-value/revalidate fields to avoid over-broad
   `snapshot_degraded` interpretation.

### V1 / Exchange Decision

- V1 recovery decision core semantics stay authoritative for live artifact
  ownership and clear/block decisions. A successful cleanup must return to truth
  and core-owned clear/block evidence.
- Bybit/OKX-style ACK-only order responses are not terminal fills. They must
  preserve order identifiers and route to order/progress/live truth before
  terminal close/recovery decisions.
- Snapshot/OI degraded data is domain-scoped evidence. It should not be treated
  as a global trading blocker unless the affected truth is required by entry,
  close, or recovery.

### Fix

- Added read-only `_post_cleanup_position_truth()` evidence after live mismatch
  cleanup. Exceptions become `truth_available=false` evidence, not state-machine
  failures.
- Added combined post-cleanup truth summary for
  `recovery.live_mismatch_flattened` and
  `recovery.live_mismatch_flatten_failed`.
- Added `cancel_ack_terminal=false`,
  `truth_required_by=pending_entry_passive_reconciliation`,
  `next_truth_probe=query_passive_order_progress`, venue, order id, and client id
  to `passive_maintenance.cancel_rest_timeout`.
- Added `endpoint`, `floor`, `current_value`,
  `targeted_revalidate_required`, and `targeted_revalidate_scope` to structural
  liquidity decision payloads.
