## Cluster CL-014-opgusdt-passive-close-stuck-under-chunk-live-flatness-and-precision

### Summary

This cluster resolves three interrelated issues with the trading loop:
1. **OPGUSDT stuck under chunk**: Maker filled 10/13, hedge matched 10/10, chunk index stuck because `maker_fill < chunk_quantity` (10 < 13). V2 was advance-blocked in the FILLED handler, looping indefinitely. We resolved this by checking live flat truth, and if not flat, escalating to `DUAL_TAKER` phase to trigger aggressive close fallback.
2. **Open order truth false-green risk**: In `_probe_venue_open_orders_flat`, when the venue did not support open order query, we returned `(True, "open_orders_query_unsupported")` which treated it as flat. This has been corrected to return `None` (untrusted) to safely retain pending state.
3. **NameError on Binance/Aster live quantity normalization**: In `VenueTransport.normalize_quantity`, the variable `venue_sym` was only defined in BYBIT/OKX branches, causing `NameError` on Binance/Aster live pathways using dynamic symbol rules. This was fixed by defining `venue_sym` at the top of the method.
4. **Hard ceiling reconcile extension tests missing**: Positive tests verifying that entries with fills past the hard ceiling are retained for reconcile extension (30s) and then aborted after extension runs out have been implemented.

### Root Fix

- Modified `_probe_venue_open_orders_flat` in `lightfee/engine/passive_close.py` to return `None` for unsupported venues.
- Defined `venue_sym = self._venue_symbol(symbol)` at the top of `normalize_quantity` in `lightfee/venues/transport.py`.
- Added `test_opgusdt_passive_close_full_closed_loop_clear` in `tests/live_harness/test_opgusdt_passive_close_stuck_incident.py`.
- Added positive tests for reconcile extension in `tests/test_live_entry_hedge_root_fix.py`.
- Added `TestBinanceAsterPrecisionFix` in `tests/test_venues_transport.py` to test `HIGHUSDT` step=1 normalization.
