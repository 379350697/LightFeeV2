### V2 Failure Chain

The high-signal path is:

```text
pending passive close retry
  -> live-flat probe proves BABYUSDT close venues flat
  -> _clear_live_flat_state() journals terminal-flat / drift events
  -> _register_close_reconciliation_after_live_flat()
  -> state.pending_close_reconciliations.append(...)
  -> AttributeError because restored state has dict-shaped queue
  -> open_positions and pending_passive_closes are never popped
  -> V1RecoveryDecisionCore clear is never reached
  -> next tick repeats the same terminal-flat cleanup
```

The observed repeated terminal-flat events are therefore not proof that cleanup
completed. They are proof that terminal evidence is emitted before a state
mutation that can still fail.

### V1 Source Comparison

V1 keeps `pending_close_reconciliations` as a typed
`Vec<PendingCloseReconciliation>` and mutates it through state-owned helpers
such as `enqueue_pending_close_reconciliation` and
`remove_pending_close_reconciliation`. V1 `process_pending_close_reconciliations`
then drains or reschedules typed work and recomputes lifecycle/risk mode.

V1 does not have a direct analogue of Python restoring a `dict` into this field:
Serde restores the field into the typed `Vec`, and V1's post-load migration only
normalizes valid pending-close tasks such as `created_cycle`. Therefore the V2
root fix is not a free-form invention, but it is also not a literal line-for-line
copy. It is the Python equivalent of V1's type boundary: restore must produce a
canonical queue before any close cleanup, supervisor, entry gate, or
reconciliation processor touches it.

V1 final close also avoids an observable half-complete state. In
`finalize_close_position_execution`, V1 updates/removes the managed open
position before emitting `exit.closed`, enqueues the typed pending-close
reconciliation through the state helper, recomputes risk mode, and persists.
`process_pending_close_reconciliations` removes a task only after successful
fill reconciliation or after final terminal-flat abandon evidence. V2's current
live-flat cleanup violates that boundary because it can journal terminal-flat
events before a later queue operation fails and before state removal/core clear.

V2 currently exposes a raw Python list field and restores it directly from the
snapshot. The runtime has V1-style recovery decision core coverage after
evidence reaches the core, but this incident fails earlier: malformed restored
state prevents passive-close cleanup from reaching the core-owned clear path.

### Root Causes

1. Snapshot shape hole:
   `pending_close_reconciliations` can be restored as a `dict`, while passive
   close registration assumes a list and calls `.append()`.

2. Cleanup atomicity hole:
   `_clear_live_flat_state()` emits terminal lifecycle/drift journals before
   queue registration and before removing `open_positions` /
   `pending_passive_closes`. If registration throws, logs say terminal-flat but
   state still contains the open/passive work.

3. V1 closed-loop pre-core hole:
   the V1 recovery decision core is present, but it is downstream of the
   failing side effect. The closed loop did not require a RED fixture where
   persisted state has a legacy/wrong container shape before passive-close
   cleanup.

4. Live-artifact owner gap:
   `MORPHOUSDT`, `MONUSDT`, and `SEIUSDT` Bybit positions are not caused by the
   `BABYUSDT` dict error directly. They are the same contract family's
   live-truth ownership problem: concrete exchange artifacts must be owned by
   local managed work, explicit recovery work, or classified as unpaired/orphan
   blockers before normal entry can resume.

5. Accepted-order versus filled-order evidence gap:
   Bybit `retCode=0` without fill fields must remain pending reconciliation /
   deadline / live-truth evidence, not final successful close evidence.

6. Downstream queue-consumer gap:
   `_process_pending_close_reconciliations`, supervisor venue coverage, and the
   entry gate all assume `pending_close_reconciliations` is a list of dict-like
   tasks. Non-dict or malformed tasks can be silently retained, skipped for
   supervision venues, or skipped for entry conflicts. That is another symptom
   of the missing V1 typed queue boundary.

### Root-Fix Plan

1. Add RED coverage from a sanitized `BABYUSDT` fixture:
   restore a state snapshot with dict-shaped `pending_close_reconciliations`,
   one pending passive close, one local open position, and exchange truth flat.
   Expected result: no raw `.append()` crash, no repeated terminal-flat event
   without state mutation, and cleanup either completes or retains state with a
   specific fail-safe reason.

2. Normalize close-reconciliation state at the restore boundary:
   `_restore_state_from_snapshot_dict()` must migrate legacy dict/map shapes
   into the canonical queue/list shape or fail with explicit migration
   evidence. Do not local-guard only inside passive close; the state object must
   not carry a shape that contradicts its contract. The serialization boundary
   must also avoid writing a poisoned non-list shape back through
   `EngineState.to_dict()`.

3. Add a V1-style state-owned enqueue helper:
   replace raw `.append()` call sites for pending-close reconciliation with a
   helper that normalizes, deduplicates, caps, and preserves venue/snapshot
   evidence like V1's typed queue boundary.

4. Make live-flat passive-close cleanup order-safe:
   terminal-flat/drift journals should not be observable unless queue
   registration, managed-state removal, risk/lifecycle recompute, persistence,
   and core clear can complete as one V1-equivalent operation. If registration
   cannot be made safe, the failure path must emit an explicit cleanup-failed
   event without pretending the position lifecycle is terminal.

5. Route the successful cleanup back through `V1RecoveryDecisionCore`:
   after live-flat cleanup removes local passive/open work, the core should see
   current exchange truth and emit one clear path (`recovery.flat` /
   `runtime.position_drift_corrected`) instead of repeated fallback terminal
   events.

6. Harden every queue consumer:
   `_process_pending_close_reconciliations`, supervisor venue coverage, and
   `_gate_pending_close_reconciliation` must either receive a normalized queue
   or emit explicit invalid-task evidence and fail safe. They must not silently
   drop supervision venues or entry-conflict evidence because an item is
   malformed.

7. Extend live-artifact owner coverage:
   add RED cases for all-venue truth where Bybit positions exist with no local
   owner (`MORPHOUSDT`, `MONUSDT`, `SEIUSDT` shape). Expected: classify as
   `unpaired_live_position` / orphan recovery work, block normal entry for the
   affected risk scope, and route to bounded flatten/reconcile/fail-closed
   handling before green production acceptance.

8. Preserve Bybit acknowledgement semantics:
   accepted close orders without fill fields must stay in pending close
   reconciliation until fill history or live flat truth proves terminality.

9. Treat market-data warnings as adjacent evidence:
   `snapshot_degraded`, `snapshot_fallback_last_good`,
   `live_scan_revalidate_required`, and `order_quote_stale_skipped` may explain
   quote gating noise, but they do not root-cause the dict append crash or the
   orphan live positions.

### Root-Fix Implemented Locally

1. `scripts/diagnose_live.py` now loads `EnvironmentFile=` entries from
   `lightfee-live.service` / `lightfee-sidecar.service` before exchange-truth
   probing, matching `verify_production_services.py`. Output records only
   `exchange_truth_env_files_loaded`, not secrets.
2. `analyze_current_state()` no longer lets stale `last_tick_ms` alone produce a
   critical report when the state is flat, exchange truth is high-confidence
   flat/no-open-orders, and `last_scan.ts_ms` shows recent runtime progress.
   Truly stale/no-progress states remain critical.
3. Hyperliquid insufficient-margin admission now carries `source`,
   `block_scope`, `blocked_until_ms`, `candidate_pair_id` / `pair_id`,
   `official_doc_url`, and `evidence_gap=false` through pending hedge, symbol
   cooldown, venue cooldown, selection/dispatch blocking, and journal events.
   Hyperliquid venue cooldowns no longer reuse the Aster-only
   `aster_max_notional_limit` reason.
4. Quote readiness evidence now exposes blocker families:
   `budget_exhausted`, `waiting_for_subscription`, `stale_quote`, or
   `invalid_quote`, plus quote ages where available.
5. Last-good sidecar fallback now emits `fallback_source=last_good_sidecar`,
   `targeted_revalidate_required=true`, and
   `targeted_revalidate_outcome=required_before_entry`. This preserves the V1
   rule that last-good can support coarse shortlist evidence only.
6. Recovery static-config probe skips now emit bounded summary evidence:
   sample symbols and omitted count, not an unbounded static-universe event
   shape.
