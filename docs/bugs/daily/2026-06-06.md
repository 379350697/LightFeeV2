# Bug Ledger - 2026-06-06

## Contract Follow-up: v1-recovery-decision-core-closed-loop

### Scope

This follow-up records the design, implementation, production rollout, and
post-review closure for the old recurring `ambiguous_exchange_truth ->
runtime.stale_recovery_block_cleared` oscillation. The first semantic fix was
deployed at `41ab11e`, then later local review closed the remaining lifecycle
edges before the next main push.

### Background

The previous exchange-truth recovery-ledger pass added the right local building
blocks: pure recovery ledger, exchange-truth normalizer, owner index,
pending-entry terminalizer, runtime ledger refresh, entry gate, and production
health alignment. Post-deploy review exposed a remaining semantic split:

- exchange truth/probe availability can create
  `exchange_truth_recovery_ledger_blocked` through
  `ambiguous_exchange_truth`.
- local-clean stale recovery-block cleanup could later emit
  `runtime.stale_recovery_block_cleared`.

That repeated block/clear pattern means V2 still has more than one recovery
decision authority.

### Decision

Create a V1-compatible pure `V1RecoveryDecisionCore` as the single semantic
authority for recovery block, recovery clear, lifecycle, entry gate, diagnostic
severity, and production-health classification.

The core is a closed loop:

```text
evidence collection
  -> truth classification
  -> ownership resolution
  -> recovery work planning
  -> lifecycle gate
  -> terminalization/management policy
  -> block or clear decision
```

The runtime remains an orchestrator. It may collect evidence and execute orders,
cancels, flattening, journals, and state transitions, but it must not carry a
separate recovery truth semantics.

### Boundary Rules

- `ambiguous_exchange_truth` is an evidence quality label, not standalone
  recovery work.
- Flat local state with no pending/open/residual/passive work plus probe timeout,
  unsupported venue, or partial venue coverage is `RUNNING_WITH_EVIDENCE_GAP`.
  It must not globally block recovery or normal entry.
- Truth unavailable while local recovery work exists is still blocking/risk-only
  because the work requires truth to proceed safely.
- A concrete live non-reduce order still maps to `orphan_maker_order` when owner
  evidence is missing.
- A concrete live position still maps to `unpaired_live_position` when owner
  evidence is missing.
- Operator fail-closed and existing explicit risk policies are preserved.
- Candidate-scoped probe errors must not mutate global runtime recovery state.

### Old Semantics To Clean Up During Implementation

1. `truth_available=False -> ambiguous_exchange_truth -> global recovery block`
   without local work/live artifact context.
2. `clear_stale_recovery_block_if_recovery_clean()` as a corrective authority.
   Legacy migration clear must be a narrow side effect after a core decision.
3. Entry gate reading a coarse recovery-ledger blocking flag directly.
4. Runtime, diagnose, and production health each interpreting truth separately.
5. Candidate scan truth errors becoming runtime recovery blockers.

### Acceptance For Future Code Work

- RED tests must reproduce the no-local-work evidence-gap oscillation before
  implementation.
- The new pure core must be the only place deciding both block and clear for
  core-owned recovery blockers.
- Normal clean entry must not become harder.
- True live artifacts and local recovery work must remain fail-safe.
- The implementation must be loosely coupled: pure core for business semantics,
  existing runtime/executors for side effects.

### Implementation Closure

Implemented a pure `lightfee/engine/recovery_decision_core.py` and routed
RecoveryLedger, runtime recovery block/clear, diagnose, and production health
through its classification. `ambiguous_exchange_truth` remains an evidence
quality label: flat/no-local-work probe gaps are
`RUNNING_WITH_EVIDENCE_GAP`, while pending/residual/passive recovery work plus
unavailable truth remains `RISK_ONLY_WAIT_FOR_TRUTH`.

Post-review closure tightened live-artifact ownership:

- a matching local open position can own live position truth only when symbol
  and venue evidence align.
- same-symbol live positions with unmatched venue ownership still become
  `unpaired_live_position`.
- same-symbol owned recovery work does not own an unrelated live maker order
  unless the order id/client id matches an owned artifact.
- diagnose count-only state, such as `pending_entry_count > 0` without a
  materialized pending-entry collection, still feeds the core as required
  recovery work.

Verification for the local implementation included focused core/ledger/runtime,
diagnose/health, startup recovery, passive-close, and full pytest suites before
deploy.

### Post-Review Root Closure Before Main Push

The first follow-up still left one old-house edge: `PassiveCloseExecutor`
could clear a legacy recovery block with a hand-built `RecoveryDecision`.
That was safer than the old stale cleaner, but it still let passive close carry
recovery-clear semantics outside the pure core.

The final local closure removes that split:

- The old `clear_stale_recovery_block_if_recovery_clean()` production function
  and `runtime.stale_recovery_block_cleared` event are gone from runtime code.
- `clear_legacy_recovery_block_via_core()` is only a migration side effect:
  it requires an explicit core decision, `clear_previous_block=True`,
  a running decision kind, `entry_allowed=True`, no `block_reason`, no operator
  fail-closed, and no remaining local recovery work.
- `V1RecoveryDecisionCore` owns the clearability set for both core-owned
  blockers and the one allowlisted legacy migration reason
  `startup_recovery_pending_work_without_open_positions`.
- Runtime startup and housekeeping no longer perform unconditional legacy
  recovery-block cleanup.
- Passive-close live-flat cleanup now builds a `RecoveryEvidenceSnapshot` and
  calls `V1RecoveryDecisionCore().decide(...)`; it no longer hand-constructs
  recovery-clear decisions.
- RecoveryLedger no longer exposes coarse `allows_new_entries` or
  `has_blocking_work`; entry gating only asks the candidate-scoped
  `allows_new_entry(candidate)`.

Final review boundary closure:

- `RUNNING_WITH_EVIDENCE_GAP` may clear only evidence-gap/legacy
  ambiguity-style blockers. It must not clear prior live-artifact blockers such
  as `orphan_maker_order` or `unpaired_live_position`; those remain fail-safe
  until fresh core evidence proves ownership or flat/no-open-order truth.
- A normal managed local open position is not recovery work by itself, which
  preserves normal V1 trading continuity under a probe gap. It becomes
  truth-required recovery work only when the evidence explicitly marks it as
  `requires_truth`, `truth_required`, `recovery_required`,
  `reconcile_required`, or `needs_recovery`, or when a recovery work item marks
  truth as required.
- Prior stale block reason alone no longer proves current recovery work. The
  current snapshot/evidence must independently feed the core decision before a
  block or clear is emitted.
