### Summary

Targeted entry OI last-good evidence was process-memory only. After a restart,
valid recent direct OI proof could no longer backstop a targeted refresh
timeout, so otherwise usable candidates cold-started on public OI availability.
The in-memory cache also retained more entries than the current hot evidence
budget needs, and prewarm work shared foreground transport capacity without a
durable cadence/preemption contract.
A follow-up execution-order review found that the durable store still had to sit
before exchange I/O on foreground cold starts, and that due prewarm had to force
real OI renewal for the required frontier instead of accepting fresh
quote-sidecar, hot, or durable OI as terminal evidence.

### Root Cause

The runtime had strict fallback semantics for a last-good OI payload, but the
payload lived only in `EntryOpenInterestRefresher._cache`. Restart discarded the
only proof-valid observation even when it was still inside the existing 30
minute hard fallback cap. Prewarm was marked diagnostic in journals, but the
refresher did not distinguish it as a lower-priority transport class.
The final audit found three remaining root gaps: the 15 minute OI cycle was
fed by optional quote prewarm extras, so the default
`entry_quote_prewarm_extra_candidate_count=0` disabled background OI coverage;
expired SQLite rows had no production cleanup call; and durable payload writes
still copied arbitrary direct-result keys instead of a strict proof-field set.
The final contract audit also found two residual invariants that needed
closure: same-venue prewarm OI transports could overlap behind the existing
venue semaphore, and equal observed timestamps could still replace the durable
row by using newer receipt/sample tie-breakers.
The lookup-order audit found two final restart/prewarm gaps: foreground
non-forced refresh could reach exchange before consulting exact durable
evidence, and due 15 minute prewarm could skip fresh quote-sidecar OI targets or
fall back to old cache evidence after a failed forced attempt.

This is market-data evidence durability and scheduling scope, not a trading
threshold issue.

### Attempts

| Attempt | Status | Why |
|---|---|---|
| Reuse only the in-process OI cache | ineffective | Safe while the process stays up, but restart loses still-valid last-good proof and forces every candidate through cold public OI again. |
| Persist arbitrary targeted refresh results | rejected | Timeouts, unsupported symbols, parse errors, stale rows, or fallback-derived payloads would contaminate future entry evidence. |
| Hydrate the full OI store at startup | rejected | It would expand memory residency and couple restart time to historical market-data volume. |

### Fix

Added `OpenInterestEvidenceStore`, a dedicated SQLite table for targeted entry
OI last-good observations keyed by venue and canonical symbol. Writes are
monotonic and accepted only for proof-valid direct `observed` payloads that are
fresh inside the 30 minute hard cap. Reads are exact-key lazy lookups and
revalidate the same proof contract, freshness, source, sample id, raw value,
unit, multiplier, and quote-normalized value before returning a fallback
payload. Fallback decoration preserves the original observation timestamp,
source, sample id, and raw OI fields.
Foreground lookup order is now hot proof-valid memory, then exact proof-valid
SQLite evidence inside the 30 minute cap, then exchange refresh. Missing,
stale, or proof-invalid durable rows are not evidence and fall through to the
real exchange attempt.

`EntryOpenInterestRefresher` now keeps a 256-entry LRU hot cache, persists only
successful direct observations, and never hydrates the full durable store.
Foreground entry refresh cancels low-priority prewarm tasks before applying the
transport bound. Prewarm is bounded to four concurrent targets, respects the
15 minute cadence, records deferred/cancelled evidence, and cannot consume the
foreground entry lane. The background OI cadence now uses the complete current
`l2_tracking_tradeable` frontier independently of optional quote prewarm extras;
the four-target setting is concurrency only and queued targets are not dropped.
Prewarm scheduling now allows at most one active or gate-waiting same-venue
transport while using available capacity for other venues first. Different
venues still share the global low-priority prewarm frontier. A distinct
same-venue direct prewarm request is deferred before it enters the prewarm
in-flight set or consumes a global low-priority slot.
Prewarm-only OI cycles retain per-target timeouts but do not apply the
aggregate foreground entry-evidence deadline to unlaunched queued targets.
Each due OI cycle deletes expired durable rows exactly once before marking the
cycle started, including empty frontiers; real durable-store cleanup failures
are logged and do not block refresh scheduling. Not-due OI cycles perform no
cleanup or refresh.
Due prewarm calls force real exchange refresh for every required resolved
frontier target, including targets whose quote snapshot already carries fresh
OI. Hot or durable cache evidence is not accepted as a completed due prewarm
attempt, and forced prewarm failures remain diagnostic rather than converting
to cache fallback success.
Durable JSON persistence is restricted to the explicit OI proof allowlist, and
SQLite conflict replacement is strictly ordered by
`open_interest_observed_at_ms`; equal observations never overwrite the stored
row regardless of newer receipt time, sample id, or payload.

Config exposes:

- `entry_open_interest_store_path`
- `entry_open_interest_background_refresh_ms`

Validation rejects empty durable paths, non-positive cache/prewarm values, and
hot cache sizes above 256.
