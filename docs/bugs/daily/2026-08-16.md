### Contract and Root Cause

An accepted order acknowledgement is not an execution fill.  V2's OKX
ACK-only fallback manufactured an `OrderFill` using a request price hint,
preflight snapshot, and zero fee.  That gave an unconfirmed hedge a false
quantity, price, and fee instead of preserving the existing uncertain-order
reconciliation path.

The same loss of evidence appeared in accounting: absent execution fees became
zero; entry construction treated absent fees as complete; close accounting
could then write PnL and `exit.closed`.  Passive maker progress added a
cumulative fee to the previous cumulative fee, even though V1 overwrites the
cumulative total and derives only the delta for the new fill interval.

V1 is authoritative here: its passive progress fee is optional and cumulative;
its close accounting derives deltas from cumulative quantity/notional/fee.
Zero remains valid only when the exchange explicitly reports zero.

### Repair

- Preserve ACK-only submissions as accepted `order.uncertain` evidence; never
  synthesize a fill from a hint or snapshot.
- Represent missing fees as `None` through transport, entry state, passive
  state, recovery, and reconciliation.  Validate finite non-negative actual
  prices and fees before final accounting.
- Persist close identities before clearing the operational position.  When any
  accounting fact is absent, keep the existing pending close reconciliation,
  do not book PnL/fees, and do not emit `exit.closed`.
- Mirror V1 cumulative maker semantics: overwrite the aggregate fee with the
  latest cumulative value, derive the new interval fee only from consecutive
  complete cumulative observations, and defer final billing if a prior interval
  has unknown fee evidence.

No opening request, retry, sizing, strategy, liquidity, or Local-L2 path was
changed.  The only added work is durable post-close reconciliation when the
exchange did not supply billing facts; normal complete fills take the existing
terminal path.
