### V1 / Exchange Decision

The current evidence does not justify a new trading-path semantic change.

- Residual repair: V1 treats residual repair as normal housekeeping, but it must not clear when trusted open-order truth says live orders still exist. If live excess is zero and trusted open-order truth is clear, the task must complete and release the pair gate. The HMSTR run ended in that state, so the production behavior is consistent unless a sanitized fixture proves the `open_orders_present` evidence was stale, local-only, or unsupported.
- Passive close / drift: V1 lets live exchange truth outrank local recovered state. NOM and ORCA resolved through live truth; RAVE `-2022` also required live flat/no-open-order confirmation before being called safe. These are covered by the passive-close/live-truth family, but RAVE still needs a fixture because diagnose sees historical residual events without a fixture conclusion.
- Admission: Bybit trading-terms and Binance/Aster leverage/max-notional rejects are deterministic exchange admission blocks. They should be classified, block repeated entry attempts, and drive cleanup if exposure exists. This run proved a real gap: Binance `-2027` is an official USD-M futures `MAX_LEVERAGE_RATIO` code, but V2 only handled the same code for Aster. The fix is exchange-doc classification, not V1 semantic copy.
- Local-L2: Binance/Aster official order-book rules still require strict continuity. High rebuild volume is not fixed by accepting broken deltas; only missing evidence or entry-blocking without diagnostics is root-fixable.
- Probe rate limits/timeouts: V1-style scoped cooldown and explicit venues are the right direction. This run shows noise, not a current false-green state. A root fix is warranted only if rate limits hide live nonzero positions or prevent closure evidence.

### Exchange Docs

- Binance USD-M error codes document `-1003 TOO_MANY_REQUESTS`, `-1007 TIMEOUT`, `-2013 NO_SUCH_ORDER`, `-2022 REDUCE_ONLY_REJECT`, `-2027 MAX_LEVERAGE_RATIO`, and `-5022 GTX_ORDER_REJECT`: https://developers.binance.com/docs/derivatives/usds-margined-futures/error-code
- Binance USD-M local order-book docs require buffering stream events, bridging to a REST snapshot, then requiring each new event's `pu` to equal the previous event's `u`; otherwise the local book must be reinitialized: https://developers.binance.com/docs/derivatives/usds-margined-futures/websocket-market-streams/How-to-manage-a-local-order-book-correctly
- Bybit V5 error docs currently list `110123`/`110125` trading-terms errors. Production saw `110126` with the same "must sign required agreement" family, so V2 should classify by both code and message text instead of relying on one exact code: https://bybit-exchange.github.io/docs/v5/error
- OKX docs define `50011` as rate-limit reached and document per-endpoint rate-limit rules; the same docs show order-detail `ordId`/`clOrdId` requirements and `51000` parameter errors around invalid required order parameters: https://www.okx.com/docs-v5/en/
