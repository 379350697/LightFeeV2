# Bug Ledger - 2026-07-29

## Cluster CL-163 - Unified Close Reconciliation, L2 Evidence, and Diagnostic Coverage

Status: corrective deployment pending; initial topology deployment proved a
paper/executable freshness-contract mismatch and was not accepted as healthy

Six-venue conclusion: Binance/Bybit/Aster/OKX/Bitget/Gate

### Evidence and Root Cause

The V2 business-contract boundary did not normalize historical and newly
created terminal accounting-only close records in one place.  Consequently,
`accounting_only_backfill`, `pending_backfill`, `blocking_trading`, and the
terminal marker could disagree after state restore or retry.  A stale recovery
truth row that did not mention the selected pair could also suppress a usable
pair-scoped truth fallback.  Terminal accounting work was eligible for the
same broad recovery refresh as a genuinely dirty pending close, which created
unnecessary account-wide reads.  In addition, the entry gate could directly
set `archived=true` after it merely observed a nonblocking contract result;
that bypassed the close runtime's journalled accounting retry and seven-day
retention lifecycle.

The L2/quote path could report a generic final-revalidation failure after a
specific missing-book, stale, sequence-gap, or clock-skew condition.  The
clock was captured before awaits, making queue delay look like exchange clock
skew.  Final BBO/OI events also lacked one safe, phase-oriented latency shape,
and diagnose could call a capped event scan healthy without saying that its
event coverage was incomplete.

### Root Fix

1. `normalize_close_reconciliation_record(...)` is the pure shared state
   boundary.  Terminal or accounting-only rows normalize to a nonblocking,
   pending-backfill terminal accounting gap on both creation and state load.
   The only pre-marker migration is a durable V1-compatible
   `passive_close_final_exchange_truth_gate` receipt with explicit flat
   position and open-order proof; generic aggregate recovery data cannot
   promote a row.
2. Close classification consumes scoped exchange truth: explicitly clean
   positions plus no open orders releases trading risk but retains accounting
   backfill; dirty truth still blocks.  Unrelated recovery truth no longer
   prevents the pair-scoped fallback.
3. Terminal accounting-only rows are excluded from the broad recovery refresh
   frontier and continue on their retained retry/archive path.  At the
   seven-day boundary their archive receipt uses the already-scoped terminal
   close proof and its hash (`exchange_truth_scope=retained_terminal_pair`),
   rather than requiring a fresh unrelated all-account scan.  A current scoped
   dirty truth still prevents that archive. Entry gating consumes the contract
   but cannot archive or mutate durable close work; only close runtime can
   journal and apply the accounting retention rule. No historical live record
   is deleted by this change.
4. Entry L2 checks refresh the wall clock after awaits and preserve the
   structural rejection reason through the final gate.  Quote/OI thresholds,
   L2 sequence rules, and fail-closed behavior are unchanged.
5. BBO/OI final-revalidation events carry allowlisted queue, HTTP, validation,
   total, generation, age, outcome, and rejection fields.  Request URLs,
   parameters, bodies, signatures, and full snapshots are not journaled.
6. Diagnose exposes `healthy_with_incomplete_event_coverage` when an event cap
   prevents it from proving a complete healthy window.

### V1 Compatibility and Remaining Proof

V1 remains authoritative for live exchange truth, passive-close terminality,
and residual recovery.  This change keeps the V1 rule that only clean
position-and-open-order truth releases trading risk; accounting proof is
separate and never reopens a flat business owner.  Aster sequence continuity
continues to use its documented `pu/u` rebuild rule; this change adds only
diagnostic/ACK/snapshot/rebuild evidence and venue-symbol backoff visibility.

Local regression coverage includes contract normalization, state restore,
close scheduling, scoped truth fallback, L2 cause propagation, safe telemetry,
diagnostic truncation, V1 recovery/private-WS/lifecycle fixtures, and catalog
coverage.  A real post-deployment open-to-close lifecycle remains required
before claiming live execution verification.

## Cluster CL-164 - Spread BBO Data-Plane Topology Regressed from Three to Four Processes

Status: local verified; deployment pending

### Root Cause

The deliberate three-process boundary (`lightfee-sidecar`,
`lightfee-spread-sidecar`, and `lightfee-live`) was removed by a later
dedicated `lightfee-spread-bbo.service` addition.  That process created a
second public BBO/metadata data plane, compact snapshot transport, metadata
cache, deployment dependency, and fourth singleton owner.  It contradicted
the established V1-compatible ownership rule: the funding sidecar owns public
discovery quotes; spread-sidecar consumes the published snapshot and has no
exchange client.

The separate data plane also made duplicate public requests compete with the
main scan.  The prior compact-snapshot implementation correctly separated a
generation-liveness clock from per-quote freshness, but it attached that
improvement to the wrong owner.

### Root Fix

1. Delete the standalone BBO app, service, compact snapshot, metadata cache,
   bulk-BBO client path, exchange-source API, and their dedicated tests.
2. Return spread-sidecar to read-only consumption of the funding sidecar
   snapshot. Snapshot liveness uses the configured sidecar budget. The current
   paper-only strategy uses explicit, bounded 30-second research sample/skew
   budgets; strict 1-second/250ms executable evidence remains unchanged for
   any future live dispatcher. No quote/OI/L2 execution threshold is relaxed.
3. Restore the systemd, deploy manifest, production verifier, and normal
   singleton topology to the three owners.  Deployment stops, disables,
   removes, and verifies the retired BBO unit before restart; singleton treats
   any residual BBO process as an unexpected fourth process and fails.
4. Preserve old BBO source strings only in diagnose so snapshots written by
   the retired version remain explainable; no current producer accepts or
   emits them.

### Regression Proof and Boundary

- A spread refresh reads the main snapshot only, including degraded and stale
  cases.  It has no direct exchange BBO path.
- A fresh main generation uses the paper-only research sampling budget. It is
  never promoted to executable quote evidence; the strict execution budget is
  still retained separately.
- A slow venue with a cached prior result does not delay a fast venue's next
  sidecar result; the slow fetch remains in the bounded background refresh
  path.  Cold-start collection remains bounded by the configured venue timeout
  and is not represented as executable quote freshness.
- Initial deployment of `b56cb08` fast-forwarded the cloud and removed the
  BBO unit. The three-process singleton check passed. The health gate correctly
  rejected acceptance because main-sidecar quote ages were 10--24 seconds while
  the paper source incorrectly reused the strict one-second executable TTL,
  yielding `sidecar_snapshot_universe_unavailable`. The corrective code keeps
  this gap observable while restoring the bounded paper-only budget; its cloud
  deployment remains pending. No order was submitted.

## Cluster CL-165 - V1 Primary Ownership Was Not Handed to the V2 Entry-Readiness Contract

Status: local root fix verified; deployment and controlled live open-to-close
verification pending

### Production Evidence

The reviewed live run had real strategy opportunities, not an empty discovery
universe: `scan.strategy_shortlist_ready=852`, `scan.no_entry_ranked_candidates=852`,
and 477 scans with nonzero strategy-tradeable candidates. Of those, 447 were
inside discovery/prewarm but outside the narrower finalization window (an
expected V1 business outcome), while 30 final-market-evidence rejections and
36 `runtime.entry_blocked_local_l2_not_ready` records needed investigation.
No order was dispatched or opened in that observation window.

The final BBO evidence records included both `waiting_for_subscription` /
`subscribed_no_message` and `missing_quote` paths. However, final
`scan.no_entry_ranked_candidates` records previously compressed specific
snapshot/reprice failures into `candidate_market_evidence_unavailable` or
`candidate_final_selection_blocked`, so the durable diagnosis could not tell
whether the blocker was quote, liquidity, OI, Local-L2, or timing.

### Root Cause

This was one lifecycle-contract split, not several independent exchange bugs:

1. The on-demand provider factory returned a WS-BBO quote-lease provider, but
   dispatch still independently enforced V1 Local-L2 readiness. A candidate
   could therefore pass selection on BBO evidence and fail later at dispatch
   for Local-L2.
2. The ranked flow chose V1 primary/shadow opportunities but did not install
   them in `EntryLocalL2SessionRuntime` or publish
   `_tracked_primary_pair_ids`. `track_opportunity(...)` had no production
   call site. A fresh pair could consequently be rejected as
   `entry_local_l2_waiting_for_primary_tracking` merely because no owner had
   been handed into the session lifecycle.
3. BBO subscription coverage lived as a separate entry-gate branch. The final
   candidate also re-reconciled the BBO stream set to one route, creating a
   cold-start/ACK/first-quote race after the V1 scope had already been chosen.
4. The final snapshot/reprice calls disabled result recording. Their exact
   terminal reason was then overwritten by a generic no-entry label.
5. The later V2 shadow-promotion helper was outside the actual ranked selector
   path, required a shadow session (which V1 deliberately does not create), and
   therefore could not make the V1 primary-hold/promotion decision. In
   addition, the ranked runner cleared the remembered primary set before every
   selection pass, so even a correct selector could never observe a hold.
6. V2 treated an unassigned-primary timestamp (`0`) as a reason to prohibit a
   replacement, whereas V1 allows it. The hold guard therefore inverted the
   initial-assignment semantics.
7. `primary_min_hold_ms` and `shadow_promotion_score_delta_bps` were absent
   from `StrategyConfig`; runtime used implicit fallbacks, offline tuning paths
   addressed fields that did not exist, and the shadow default was zero rather
   than V1's bounded two-candidate default. This made the promotion policy
   neither explicit nor operable.

V1's compatible behavior is to allocate a bounded primary+shadow ownership
scope before final selection, retain that ownership through the entry window,
and require the selected primary to be dual-ready. V1 does not allow a
selection-only quote path to bypass the final local-book contract.

### Root Fix

1. `OnDemandEntryReadinessProvider` composes V1 Local-L2 and WS-BBO quote
   lease checks into one final-entry decision. It reports the blocking
   component and bounded component evidence; selection has one provider call,
   while dispatch remains a race-only fail-closed recheck.
2. When Local-L2 is enabled, the ranked flow now performs the V1 ownership
   handoff before Local-L2 warming: it writes the primary pair set and calls
   `entry_l2_sessions.track_opportunity(...)` for selected **primaries only**.
   Shadows remain bounded warm-pool candidates, exactly as V1, rather than
   acquiring independent sessions. Every prewarm pass invokes V1-style
   `close_missing(active_primaries)`; the 64-pair sticky set protects brief
   rank churn without allowing unbounded stale session ownership. A later
   missing HOT book truthfully becomes
   `entry_local_l2_waiting_for_dual_ready`, rather than a fabricated
   not-tracked state.
3. WS-BBO subscription/budget coverage is quote-readiness evidence within the
   composed provider. BBO prewarm uses the same V1 primary+shadow scope, keeps
   it warm through the final loop, and final revalidation no longer shrinks
   the stream set to a single candidate. Its prewarm is bounded to 100 ms; a
   timeout falls back to the existing bounded final-candidate activation rather
   than assuming a subscription is usable. Diagnostics retain both the composed
   `contract_provider` and the WS-BBO `quote_lease_provider`. This changes
   ownership timing only; it does not treat a subscription as a quote or relax
   quote age/skew, Local-L2, OI, funding, account-truth, or final-window rules.
4. Entry-scope primary selection, Local-L2 data-plane activation, and the final
   gate consume the same composed effective-provider predicate. The legacy
   compatibility predicate remains limited to non-entry lifecycle work such as
   post-fill recovery, so it cannot silently remove current entry ownership.
5. Catalog, admission, final snapshot, repricing, quote/OI exception, account,
   and dispatch stages record their actual contract blocker,
   and `scan.no_entry_ranked_candidates` now carries bounded per-pair reasons
   plus prewarm/tracked scope counts. Generic labels remain only when no
   concrete contract reason exists.
6. Primary ownership and shadow promotion now occur inside
   `_select_v1_entry_tracked_scope`, the only ranked-scope decision point. It
   retains an eligible in-scope primary through V1's hold window, fills vacant
   slots from the current ranked frontier, then considers the best shadow only
   against the worst primary after the V1 hold, score-delta, execution, and
   direct Local-L2 book-readiness checks. Shadows use the same HOT/WARM,
   fresh, uncrossed book contract as primaries but never acquire a session.
   The runner preserves the previous primary set until this decision has used
   it; transiently failed pairs remain excluded.
7. The V1 defaults are now explicit and validated in the unified strategy
   contract: two bounded shadows, a 15-second primary hold, and a 3.0-bps
   promotion delta. The shared non-negative-integer validator rejects strings,
   booleans, fractions, and non-finite values at startup rather than allowing a
   type error or implicit runtime fallback.

### Regression Proof and Remaining Boundary

Local regressions prove all of the following:

- V1 primary ownership and a Local-L2 session exist before BBO prewarm, while
  a shadow has warm-pool coverage but no session; a no-book fixture now reports
  dual-ready rather than not-tracked.
- A two-candidate final flow warms the V1 scope once and passes an empty
  activation set to final quote revalidation, preventing per-candidate stream
  reconciliation churn.
- A final liquidity rejection remains
  `perp_liquidity_stale_blocking` in the no-entry event and per-pair summary;
  it is not rewritten as a generic market-evidence failure.
- A catalog rejection remains `unsupported_symbol` in its pair-level no-entry
  record rather than becoming `candidate_admission_blocked`; a BBO prewarm
  timeout is bounded and explicitly journaled before final activation retries.
- BBO-only provider/lease fixtures explicitly disable Local-L2 so their scope
  remains quote-lease behavior; composed-provider fixtures prove Local-L2 has
  precedence when it is enabled.
- A primary survives ordinary rank churn during its V1 hold window; a direct
  HOT/WARM shadow can promote after the hold without a shadow session, while a
  cold shadow cannot. The zero-assignment sentinel permits the initial V1
  replacement decision, and invalid promotion configuration fails closed at
  config validation.

The local suite is green. This record does **not** claim deployment health or
real order behavior: the required next proof is a separately authorized,
small controlled live candidate → open → close lifecycle with exchange truth.
Hyperliquid remains outside this six-venue conclusion.
