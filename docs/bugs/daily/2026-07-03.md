## Cluster CL-147 - Diagnose Consumes Exchange Truth Ledger for Legacy Close Gaps

Status: `0858837` deployed/cloud verified for close-gap classification. The
post-deploy explicit 7-venue diagnose then exposed separate CL-149
full-history residual gate drift.

- Cards: [passive-close-terminal-flatness](../cards/passive-close-terminal-flatness.md)

### Production Symptom

After CL-146, the canonical lifecycle ledger could prove historical project
record gaps by exchange fills and append-only corrections. The latest deploy
still showed a healthy flat/no-open-orders production gate, but
`diagnose_live --since-deploy` could keep reporting
`close_truth_gap_legacy_inferred` for accepted-order truth gaps that had
closed through legacy terminal-flat events even when the same position had
complete exchange open/close fill coverage.

That was not a trading-risk problem. It was a diagnosis-consumption gap:
diagnose had not yet made the exchange-truth ledger the final authority for
legacy close normality.

### Root Cause

`_build_resolved_order_truth_gap_summary()` matched accepted-order truth-gap
registration to either explicit `exit.accepted_order_truth_gap_resolved` or
legacy terminal-flat evidence. Legacy matches were always counted as
`legacy_inferred_count`, regardless of whether
`build_exchange_truth_lifecycle()` could prove the position was
`exchange_lifecycle_complete` with both close legs covered.

That left three truth layers out of sync:

- CL-144 made ACK-only close gaps explicit and kept old legacy logs visible.
- CL-146 built the unified exchange-truth lifecycle ledger and proved 67/70
  historical records exchange-complete.
- `diagnose_live` still treated ledger-complete legacy close gaps as stale
  explicit-lifecycle debt.
- Production legacy `order.filled` close statements also carried
  venue-normalized `leg` and close-side `side` but not always `phase`,
  `source`, or `tradeSide`; the ledger therefore needed to infer close/open
  phase from `long+sell`, `short+buy`, `long+buy`, and `short+sell`.

### V1 / Exchange Decision

- Exchange truth remains authoritative over project-local `exit.closed`.
- Legacy terminal-flat evidence is not enough by itself.
- If the unified ledger proves both open legs and both close legs covered by
  exchange fill truth, the legacy close is a project-record gap already closed
  by the ledger, not a current health fingerprint.
- If exchange fill evidence is missing or incomplete, keep
  `close_truth_gap_legacy_inferred` visible.
- Venue-normalized `leg+side` is valid fill-phase evidence when explicit
  `phase/source/tradeSide` is absent.

### Fix

- `exchange_truth_ledger._fill_phase()` now infers close fills from
  `leg=long, side=sell` and `leg=short, side=buy`, and open fills from the
  opposite venue-normalized pair, while preserving explicit `phase`,
  `source`, and `tradeSide` priority.
- `diagnose_live` now runs matched legacy truth-gap positions through
  `build_exchange_truth_lifecycle()`.
- Legacy truth-gap matches with `exchange_lifecycle_complete` and both close
  legs covered move into:
  `ledger_closed_legacy_inferred_count`,
  `ledger_closed_legacy_inferred_positions`,
  `ledger_closed_legacy_inferred_identities`, and
  `ledger_closed_legacy_project_statuses`.
- Ledger-closed legacy gaps add
  `exception_conclusions.ledger_closed_legacy_truth_gap =
  closed_by_exchange_truth_ledger` and no longer add the
  `close_truth_gap_legacy_inferred` fingerprint.
- Legacy gaps without exchange-complete ledger proof still keep
  `legacy_inferred_count` and the existing fingerprint.

| local GREEN | production-shaped legacy `order.filled` with `leg/side` but no `phase/source` | `exchange_lifecycle_complete`, `legacy_exit_closed_project_record_gap` |

### Follow-up

- Deploy before calling this production verified.
- After deploy, rerun compact since-deploy diagnose on all seven venues. If the
  deploy-window legacy closes have exchange-complete ledger evidence, the
  health summary should not keep `close_truth_gap_legacy_inferred`; it should
  show the ledger-closed bucket instead.
- Keep CL-135/CL-144 as historical context: explicit ACK-only lifecycle remains
  preferred for new close paths, while CL-147 prevents already proven
  exchange-complete legacy records from staying as stale health debt.

## Cluster CL-148 - Terminal Flat Legacy Close Gap Into Exchange Truth Ledger

Status: local verified; deploy pending.

- Cards: [passive-close-terminal-flatness](../cards/passive-close-terminal-flatness.md)

### Production Symptom

After deploying CL-147, explicit 7-venue read-only diagnose showed all venues
flat/no-open-orders and `gate_passed=true`, but the all-history window still
reported `close_truth_gap_legacy_inferred` for
`entry-1783072433951-LABUSDT`.

The position's current retained events had:

- `exit.accepted_order_truth_gap_registered` for Bybit short close ACK-only.
- `exit.accepted_order_truth_gap_retry_blocked` because open-order truth was
  temporarily unavailable.
- `runtime.position_lifecycle_terminal` with exchange truth available,
  `positions_flat=true`, `open_orders_flat=true`, and Aster/Bybit position
  quantities both zero.
- No retained close fill statement in the diagnose event window.

So the exchange risk was closed, but accounting/order-fill evidence remained
incomplete. Treating this as the same `close_truth_gap_legacy_inferred`
fingerprint hid the distinction between a live risk gap and a terminal-flat
accounting evidence gap.

### Root Cause

CL-147 only let the diagnose layer suppress legacy close noise when
`build_exchange_truth_lifecycle()` could prove
`exchange_lifecycle_complete`: both open legs and both close legs covered by
exchange fill truth.

For older rotated-window evidence, the ledger could see terminal live-flat
exchange truth but not enough order-fill statements to compute full lifecycle
or PnL. The ledger exposed no separate terminal-flat evidence field, so
diagnose had only two buckets:

- complete exchange fills -> `ledger_closed_legacy_inferred_*`;
- anything else -> `legacy_inferred_count` plus
  `close_truth_gap_legacy_inferred`.

That was too coarse for legacy close convergence.

### V1 / Exchange Decision

- Do not call this `exchange_lifecycle_complete`; missing close statements
  still means no complete accounting/PnL sample.
- Do not call it a live close risk if exchange truth proves flat positions and
  empty open orders.
- Classify it as terminal flat exchange-truth evidence with accounting gap:
  safe for entry gate, excluded from optimization/accounting samples until
  fills are present.

### Fix

- `PositionLifecycleTruth` now carries `terminal_flat_truth` when a terminal
  event includes exchange truth with `positions_flat=true` and
  `open_orders_flat=true`.
- `_project_record_status()` now returns
  `terminal_flat_exchange_truth_accounting_gap` for terminal-flat exchange
  truth without complete close fill coverage.
- `diagnose_live` moves matched legacy truth gaps with that ledger status into:
  `ledger_terminal_flat_legacy_inferred_count`,
  `ledger_terminal_flat_legacy_inferred_positions`,
  `ledger_terminal_flat_legacy_inferred_identities`, and
  `ledger_terminal_flat_legacy_project_statuses`.
- The production gate adds
  `exception_conclusions.ledger_terminal_flat_legacy_truth_gap =
  terminal_flat_exchange_truth_ledger_evidence_gap` and does not add the
  `close_truth_gap_legacy_inferred` fingerprint for those positions.

### Verification

|---|---|---|
| cloud read-only before fix | deployed `2503399`, explicit 7-venue diagnose | 7 venues flat/no-open-orders, gate passed, but `legacy_inferred_count=2`, `legacy_inferred_positions=[entry-1783072433951-LABUSDT]`, fingerprint `close_truth_gap_legacy_inferred` remained |
| local GREEN | `test_terminal_flat_exchange_truth_gap_is_not_complete_but_is_classified` | classification stays `evidence_incomplete`, project status is `terminal_flat_exchange_truth_accounting_gap`, PnL remains zero |
| local GREEN | `test_acceptance_gate_moves_terminal_flat_legacy_truth_gap_to_ledger_evidence_gap` | `legacy_inferred_count=0`, `ledger_terminal_flat_legacy_inferred_count=1`, no `close_truth_gap_legacy_inferred` fingerprint |

| cloud explicit 7-venue after deploy | deployed `0858837`, `diagnose_live --json --venues bitget,okx,binance,bybit,aster,gate,hyperliquid --max-events 200000` | no close-gap fingerprint remained; exchange truth was available for all 7 venues with no missing required venues, but the gate failed on separate historical `residual_events_present`, tracked as CL-149 |

### Follow-up

- Keep CL-148 classified as an accounting evidence gap, not complete PnL truth.
- Close CL-149 before using full-history explicit 7-venue gate as final
  production acceptance evidence.

## Cluster CL-149 - Completed Historical Residuals With Active Positions

Status: local verified; deploy pending.

### GitNexus Keys

- Fingerprints: `residual_events_present`, `residual_lifecycle_complete`,
  `active_positions_with_capacity`, `acceptance_pending_open_lifecycle`
- Components: `diagnose-live`, `residual-repair`, `production-gate`
- Symbols: `_build_production_acceptance_gate`
- Files: `scripts/diagnose_live.py`, `tests/test_diagnose_live.py`
- Watch:
  `production_acceptance_gate.residual_count`,
  `production_acceptance_gate.unclosed_residual_lifecycle_count`,
  `production_acceptance_gate.residual_lifecycle_complete`,
  `production_acceptance_gate.blocking_reasons`
- Cards: [residual-repair-live-truth](../cards/residual-repair-live-truth.md)

### Production Symptom

After deploying CL-148 at `0858837`, compact since-deploy diagnose passed:

- `gate_passed=true`
- `blocking_reasons=[]`
- no pending entry, close, close reconciliation, residual repair, or residual
  events in the deploy window
- two current owner-managed open positions:
  `entry-1783093934706-LABUSDT` and
  `entry-1783094015818-BIRBUSDT`
- exchange truth showed Binance long and Bybit short for both symbols, and no
  open orders

The explicit all-history 7-venue diagnose correctly queried all required
venues and found no missing venue truth, but failed the production acceptance
gate:

- `blocking_reasons=["residual_events_present"]`
- `residual_count=70`
- `pending_residual_repair_count=0`
- `closed_residual_lifecycle_count=4`
- `unclosed_residual_lifecycle_count=0`
- all 7 venues were queried; only Binance/Bybit had the two current managed
  positions; every venue had `open_order_count=0`

So the live exchange state was not bad. The failure was a stale full-history
diagnostic blocker.

### Root Cause

`_build_production_acceptance_gate()` had only two paths to consider residual
events closed:

- no residual events at all; or
- the whole account was locally/exchange flat and the residual lifecycle had no
  unclosed residual keys.

It had a narrower active-owner exception, but that required every residual
event in the all-history window to be scoped to the currently active owner.
That is too strict for full-history explicit venue diagnostics: old completed
residuals from `ZKPUSDT` / `AERGOUSDT` should not be re-scoped to the current
LAB/BIR owners, and they should not require the whole account to be flat while
current managed positions are legitimately open.

The lifecycle summary had already proved the important condition:
`unclosed_residual_lifecycle_count=0`. The gate ignored that standalone
terminality when active positions were present.

### V1 / Exchange Decision

- Residual repair remains blocking when there is current pending residual work
  or any unclosed residual lifecycle key.
- Completed historical residual lifecycle is not a current production blocker
  when `pending_residual_repair_count=0` and
  `unclosed_residual_lifecycle_count=0`.
- Current owner-managed open positions do not invalidate completed residual
  history. Exchange truth for those open positions is checked separately by
  active-position capacity and open-order truth.

### Fix

- Add `residual_lifecycle_complete` to the production gate.
- Set it only when residual events exist, there are no pending residual
  repairs, and the residual lifecycle has no unclosed keys.
- Include this state in `residual_lifecycle_closed`, so completed historical
  residuals no longer add `residual_events_present`.
- Keep true current blockers unchanged:
  `local_pending_residual_repairs_present` still fires from local state, and
  `residual_events_present` still fires when residual lifecycle has unclosed
  keys.

### Verification

| Environment | Evidence | Result |
|---|---|---|
| cloud read-only before fix | deployed `0858837`, explicit 7-venue diagnose | all venues queried; current open positions were Binance/Bybit LAB/BIR with no open orders; gate failed only on `residual_events_present` despite `unclosed_residual_lifecycle_count=0` |
| local GREEN | `test_acceptance_gate_accepts_historical_completed_residual_with_active_positions` | completed old residuals no longer block a current owner-managed active position; `residual_lifecycle_complete=true`, no `residual_events_present`, gate passes |
| local GREEN | `test_acceptance_gate_accepts_completed_residual_for_owner_managed_active_position` | existing active-owner residual exception still passes |

### Follow-up

- Deploy before calling CL-149 production verified.
- Post-deploy explicit 7-venue diagnose should keep the two current managed
  positions visible if still open, show no open orders, and pass the gate with
  `residual_lifecycle_complete=true` instead of
  `residual_events_present`.
