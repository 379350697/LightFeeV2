### Summary

V1/V2 source comparison found several close-path semantic gaps behind the
question "why did force close not trigger?" The deployed V2 code had helpers
for some V1 concepts, but several were not connected to the active runtime
path or did not propagate into inner force/compensation paths.

### Root Cause

| Issue | Classification | Root cause |
|---|---|---|
| `settlement_force_close` did not trigger | V2 semantic drift | `force_close_due()` existed only as a helper/test surface; runtime normal exit called `standard_close_reason()` directly, so aligned force-close deadlines degraded into `funding_capture`. |
| Death-line single-side protection touched both legs | V2 semantic drift | `RiskExecutionPlan` did not carry V1 `select_single_side_protection_target()` venue/side/stage. Supervisor logged single-side protection but called full `execute_close()`. |
| Residual repair repeated Bybit `110072` | Coverage split | Ordinary close and entry cleanup had duplicate-client reconciliation, but residual repair used deterministic `residual_repair` CID and only rescheduled on duplicate. |
| Close compensation/hard-stop duplicate lacked evidence | Coverage split | `_compensate_close_leg_exposure()` swallowed placement errors into flat rechecks and did not query Bybit order evidence or record a reconciled compensation leg. |
| Risk/protection PnL buckets stayed zero | V1 state fidelity drift | V2 had `risk_delever_*` and `protection_*` state fields but close writeback only updated generic realized PnL/fees. |
| Full V1 risk-delever L2 sizing | Still open | GitNexus impact for `build_risk_execution_plan` is HIGH. V2 still lacks the full V1 `risk_delever_sizing_plan()` integration with true-L2/top-book capacity, slippage, hot local-L2 requirement, and min-notional residual checks. This needs a dedicated high-risk change, not a cosmetic frequency reduction. |

### V1 / Exchange Decision

- V1 copy: `settlement_force_close` is evaluated outside standard close
  reasons and overrides ordinary funding close once force deadline is due.
- V1 copy: death-line protection selects exactly one venue/side/stage before
  entering fail-closed; it must not silently become a synchronized two-leg
  close.
- Exchange semantics: Bybit `110072 OrderLinkedID is duplicate` is an
  idempotency conflict. Existing V2 duplicate reconcile helper is reused for
  residual repair and compensation instead of creating a new exchange rule.
- V1 state fidelity: risk-delever and protection close PnL remain separately
  attributable in position state.

### Attempts

| Attempt | Status | Why |
|---|---|---|
| Treat force-close as ordinary `standard_close_reason` | ineffective | It returns `funding_capture` before `settlement_force_close`, losing V1 priority. |
| Reuse full `execute_close()` for death-line protection | ineffective | It submits both legs, which violates V1 single-side protection semantics. |
| Let residual/compensation duplicate paths retry blindly | ineffective | Deterministic CIDs can reproduce Bybit `110072` and leave insufficient order evidence. |
| Implement full risk-delever L2 sizing in this patch | deferred | Impact is HIGH and requires wiring runtime/local-L2 execution-liquidity snapshots into risk planning. |

### Fix

- Runtime normal exit now checks `force_close_due()` first and routes due
  aligned positions as `settlement_force_close`.
- `RiskExecutionPlan` now carries single-side protection target
  `protection_venue`, `protection_side`, and `protection_stage`, derived from
  degraded venue or health ratio.
- Supervisor now executes death-line protection through a single-leg reduce-only
  IOC close path, logs success/failure/unavailable evidence, and then enters
  fail-closed.
- `CloseExecutor.execute_single_side_protection()` submits one selected
  reduce-only IOC leg and reuses the existing close-leg retry and Bybit
  duplicate reconciliation machinery.
- Residual repair now reconciles Bybit duplicate CIDs with
  `reconcile_bybit_duplicate_client_order()`, clears live-flat/full evidence,
  retries partial live exposure with a fresh CID, and records structured
  `recovery.residual_repair_duplicate_client_order_reconcile_result`.
- Close compensation now reconciles Bybit duplicate compensation orders,
  records `exit.compensation_duplicate_client_order_reconcile_result`, and
  returns a reconciled fill leg when the old order is proven filled.
- Close writeback now fills V1 risk/protection realized PnL buckets based on
  close reason.
