## CL-157 — Gate 订单状态对账能力（第三处 gate 缺口） → closed

### Symptom

Bybit key 轮换（见 09-19 ledger）后 runtime 恢复仍卡死：pending entry
`entry-1789696320918-LSKUSDT` 的 gate 对冲单 `103019842165780963`
（size -57，实际已成交）每次 reconcile 都
`uncertain → reconcile_again_after_backoff`，runtime 持续 fail-closed
（`owned_pending_entry_live_conflict → BLOCK_OR_FLATTEN_LIVE_ARTIFACT`），
每 ~15 秒一个生命周期地重复。

### Root cause

`transport.fetch_order_status` 只有 BYBIT/BINANCE/OKX/BITGET 四个分支，
GATE 落到 `return None`（ORDER_STATUS 契约早已定义：
`GET /api/v4/futures/usdt/orders/{order_id}`，从未实现）。同族第三处：
`fetch_order_fill_reconciliation`、`discover_historical_close_fill_
reconciliation` 之后，gate 订单状态是最后一个缺失的对账能力。

### Repair (`80ba91b4`)

- transport 新增 `_fetch_order_status_gate`：订单行取执行数量
  （abs(size)-abs(left)）、方向（size 符号）、fill_price 缺失时用
  my_trades VWAP 兜底；佣金来自订单自身的 my_trades 行（binance
  userTrades 同型增补）；404 ORDER_NOT_FOUND → None fail-closed；
  client-order-id-only 查询无 wire 通道 → None fail-closed（Gate 不存
  client order id）；fill price 不可证 → 保持不可用而不是编造均价。
- `GateAdapter.fetch_order_fill_reconciliation` 委托 transport。
- `TestGateOrderStatus`（6 用例 wire fixtures：filled sell / open
  zero-fill / cancelled-with-leftover / 404 / cid-only / 委托）；RED 于
  pre-fix 树（3 wire 用例失败），GREEN 后全过；transport 全套 502 通过。
