# Bug Ledger - 2026-07-31

## Cluster CL-169 - Funding-Interval Proof Cache and Bounded Cold Warmup

Status: local root fix verified; deployment and live evidence pending

### Evidence and Root Cause

The Binance/Aster-compatible ticker endpoints do not provide an explicit
funding interval for every contract. V2 attempted to infer it by requesting two
historical funding settlements for every missing symbol during the public
sidecar refresh. At eight concurrent requests under a three-second total budget,
a cold process covered only an initial fraction of a several-hundred-symbol
market; all remaining rows became `funding_interval_ms_invalid` and were
subsequently described by the liquidity lifecycle as
`liquidity_quote_unavailable`. The latter was derived from the discarded funding
quote, not evidence that BBO or OI had failed.

Prior restart handling compounded this: it copied an interval from the prior
snapshot into memory with the current process time. The snapshot did not retain
a source-specific interval-proof timestamp, so restart could extend unverified
evidence as if the exchange had just supplied it.

### Root Fix

1. Persist only validated exchange-derived interval proof in a compact, atomic
   sidecar sibling cache: venue, symbol, interval, proof source, and original
   observation timestamp.
2. On restart, validate and load only configured-venue entries while preserving
   their original timestamp. A legacy snapshot is no longer allowed to create
   fresh cadence proof.
3. A valid local proof suppresses historical funding-rate HTTP during normal
   scans. Missing or expired proof uses a deterministic rotating batch of at
   most 48 symbols no more than once per 30 seconds, instead of a full-universe
   fan-out per refresh.
4. There is no default Binance/Aster interval. A symbol without current
   venue-derived proof remains interval-unknown and is excluded by the existing
   funding admission contract. BBO, Local-L2, OI, liquidity, account-truth, and
   final execution checks are unchanged.
5. Remove the unreferenced `LiquiditySource` and its
   `MarketDataClient.fetch_perp_liquidity()` wrapper. It was a second public
   client that could re-enter the funding fetch path without sidecar-owned
   cadence proof; OI/volume remain supplied by the sole `ExchangeSource` path.

### Regression Proof and Remaining Boundary

Focused market-data, sidecar, source, snapshot-freshness, and funding-entry
degradation suites pass: 290 passed, 10 skipped. Tests cover bounded rotating
cold repair, cache schema/venue validation, atomic persist shape, preservation
of the original proof clock, and rejection of the old snapshot-as-fresh path.

Deployment must verify the cache is populated after a healthy interval proof,
survives a sidecar restart, and leaves Binance/Aster coverage stable without
all-symbol `fundingRate` bursts. A new interval change or cache expiry must
remain fail-closed until refreshed venue proof arrives.
