# 2026-06-18

## Cluster CL-094 - ZECUSDT entry route semantic closure after latest deploy

| Status | Severity | Family | Modules | Files |
|---|---|---|---|---|
| fixed locally; cloud deploy pending | high | venue-contract + maker-event-admission + pending-entry-hard-ceiling + diagnostic-lifecycle-drift | aster-v3, passive-maker, pending-entry, diagnose-live, v1-lifecycle-closure | `lightfee/venues/aster_v3.py`, `lightfee/engine/passive_maker_runtime.py`, `lightfee/engine/runtime.py`, `scripts/diagnose_live.py`, `lightfee/engine/v1_lifecycle_closure.py` |

### Evidence

- Latest cloud deploy `94487e4` ended safe: local pending/open/close/residual
  counts were zero and exchange truth was high-confidence flat/no-open-orders.
- The since-deploy window was not semantically clean. Two ZECUSDT entries
  aborted only after pending lifetimes around 208-214 seconds, beyond the V1
  pending-entry hard ceiling of 120 seconds.
- Aster V3 hedge submit failed with `-1106 PARAM_NOT_REQUIRED` because the
  MARKET/IOC hedge body sent `timeInForce=IOC`, which Aster rejects for that
  request shape.
- Bybit maker reprice/cancel-replace repeatedly produced `110007 Available
  balance is insufficient`; the maker-event lane treated this as a repeatable
  generic error instead of a terminal opening-risk admission block.
- `phase_duration_summary` showed hard-over-budget samples with empty
  `action_taken`, and V1 lifecycle closure did not map
  `entry.hedge_drive_cancel_replace`, `runtime.maker_event_lane_wake`,
  `runtime.maker_event_reprice`, or `runtime.maker_event_reprice_error`.

### Fix

- Aster V3 now omits `timeInForce` for MARKET/IOC hedge or cleanup requests;
  passive limit submits still send the required post-only TIF.
- Maker-event reprice classifies Bybit `110007` as
  `insufficient_balance_admission_blocked`, marks that entry route as
  terminally blocked for new opening reprice attempts, and keeps reduce-only
  close/recovery paths separate.
- Pending-entry hard ceiling no longer grants a 30s local retention extension
  after the 120s hard limit. Positive-fill pending entries emit
  `pending_entry.hard_ceiling_reconcile_before_abort` and then immediately
  continue through the existing abort/cleanup truth path.
- `diagnose_live.py` exposes top-level `phase_duration_summary` and fills
  hard-over-budget `action_taken`/`action_evidence_kind` fields so final
  flatness cannot hide missing budget actions.
- V1 lifecycle closure now maps the maker-event and hedge-drive events to the
  correct phases, removing the unmapped-event drift.
