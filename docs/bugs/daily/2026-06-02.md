### Production Evidence

After CL-027 cleared the older ARIA pending-entry blocker, the post-deploy
window became a clean WS BBO provider effect window. The provider was active
and opened one position, but it still emitted high missing-quote counts:

| Window | Evidence |
|---|---:|
| Since `bb3f239` (`2026-06-01T15:31:00Z`) | `runtime.entry_blocked_local_l2_selection=517` |
| Same window | `entry_ws_bbo_quote_lease_missing_quote=512` |
| Same window | `entry_ws_bbo_quote_lease_stale_quote=5` |
| Same window | `runtime.entry_blocked_quote_lease/stale_quote_lease=29` |
| Same window | `execution.entry_selected=10`, `runtime.entry_dispatched=10`, `entry.opened=1` |

The stream-state split was the key evidence. The missing quote events were not
mostly "subscribed but no quote" failures. They were dominated by
`tracked=false` stream states, for example Aster long `248`, Aster short `135`,
Binance short `127`, Bybit long `117`, Bybit short `101`, and OKX short `74`.
There were no tracked streams with `message_count=0` in the sampled aggregate.

### Root Cause

CL-026 fixed the original lifecycle bugs: prewarm timing, ranked budget order,
current Binance public WS endpoint, and stream control-error evidence. This
follow-up is a separate coverage-consistency miss:

1. Production did not explicitly configure `entry_ws_bbo_per_venue_budget`, so
   it used the code default of `4` per venue.
2. Real candidate sets were much larger than four symbols per venue.
3. Budget-out candidates could still reach final entry provider decision.
4. Those candidates had no cached quote and no tracked BBO stream, so the
   provider correctly failed closed as `entry_ws_bbo_quote_lease_missing_quote`.

This is not a Local-L2 regression and not wrong-price entry. It is opportunity
coverage loss plus noisy missing-quote diagnostics.

### Fix

- Increase the default `entry_ws_bbo_per_venue_budget` from `4` to `10`.
- Add a WS BBO subscription coverage guard before provider quote validation:
  if a candidate has no cached quote and its venue/symbol stream is not tracked,
  block it as `entry_ws_bbo_quote_lease_waiting_for_subscription` with stream
  state evidence instead of calling the provider and reporting generic
  `missing_quote`.
- Preserve normal fail-closed behavior for tracked streams with missing quotes
  or stale quotes. Those remain provider-level quote failures and keep their
  evidence.
- Update example configs so operators see the explicit `ws_bbo_quote_lease`
  option and the new budget default.

No Local-L2, order placement, sizing, close, residual repair, or recovery
semantics changed.

### Acceptance

Accepted locally, pending commit/deploy and production-window verification. The
expected production effect is that budget-out WS BBO candidates stop inflating
generic `entry_ws_bbo_quote_lease_missing_quote`; they should either be covered
within the larger per-venue budget or be classified as
`entry_ws_bbo_quote_lease_waiting_for_subscription` until coverage catches up.
`stale_quote_lease` remains a correct fail-closed guard when a venue does not
publish fresh BBO within the configured TTL.
