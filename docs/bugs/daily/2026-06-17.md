# 2026-06-17

## Cluster CL-093 - entry selected total lifecycle SLA and artifact duration diagnostics

| Status | Severity | Family | Modules | Files |
|---|---|---|---|---|
| fixed locally; cloud deploy pending | high | long-lived-pending-entry + close-latency-diagnostics + quote-rewarm-classification | pending-entry, live-runtime, diagnose-live, v1-lifecycle-closure | `lightfee/engine/runtime.py`, `lightfee/engine/entry_sync.py`, `scripts/diagnose_live.py`, `lightfee/engine/v1_lifecycle_closure.py` |

### Evidence

- Latest cloud state before the fix was finally safe: no local open/pending/close/residual work and all venues flat/no-open-orders.
- The since-deploy event window still showed a timing bug: `BRUSDT` spent about 759 seconds from `execution.entry_selected` to `entry.aborted`.
- The existing pending-entry hard ceiling was based on `PendingEntry.created_at_ms`, so maker/open-order evidence could consume a much longer selected-to-terminal window before the pending hard ceiling became active.
- Close paths such as `XVGUSDT` terminalized correctly, but repeated `exit.passive_close_missing_l2_or_tick` needed explicit latency/data-quality visibility.

### Fix

- `EntrySyncExecutor` now stores `entry_selected_at_ms` on pending-entry metadata.
- `LiveRuntime._pending_entry_terminalization_budget()` now has an independent `entry_selected_terminal_sla_ms` budget, defaulting to 300 seconds.
- When the selected-to-terminal SLA is exceeded, runtime emits `pending_entry.long_lived_pending_entry` and routes through the existing abort/finalize/cleanup path. Maker-open-order truth remains fail-closed; the fix does not fake flat state.
- `diagnose_live.py` now exposes `artifact_duration_summary` under `entry_outcome_summary`, including selected-to-terminal, pending-created-to-terminal, close-created-to-terminal, long-lived pending count, and close data-quality warning count.
- A lightweight lifecycle SLA table now centralizes the missing budgets:
  candidate lease 60s, selected-before-submit 15s, maker resting 30s/60s,
  pending-entry 60s/120s, selected-to-terminal 120s/300s, close 60s/300s,
  and recovery hard 300s. It is a diagnostic/fail-closed budget table, not a
  strategy/admission/sizing change.
- `diagnose_live.py` now also exposes `phase_duration_summary`, with phase,
  symbol, venue, age, budget, over-budget status, action taken, and terminal
  truth source, so future since-deploy review can flag BRUSDT-style drift even
  when final exchange truth is flat.
- Quote rewarm diagnostics now classify `still_stale` and `timeout` by `venue:symbol`.
- `pending_entry.long_lived_pending_entry` is explicitly mapped to V1 lifecycle phase `PENDING_ENTRY`.
