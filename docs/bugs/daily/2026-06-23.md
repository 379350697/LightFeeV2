## Cluster CL-107 - Entry OI market-data root fix after admission blockers

| Status | Severity | Family | Modules | Files |
|---|---|---|---|---|
| local green; deploy pending | high | entry OI evidence, sidecar slow enrichment, market-data admission blockers, Hyperliquid OI normalization | market-data-client, sidecar, runtime-targeted-refresh, bug-ledger | `lightfee/venues/market_data.py`, `lightfee/engine/market_data_runtime.py`, `tests/venues/test_market_data_client.py`, `tests/test_runtime_snapshot_freshness.py`, `tests/sidecar/test_sources.py` |

### Fingerprint

`entry_market_evidence_block OI unavailable; Binance/Aster entry OI reuses full fetch_funding_tickers; sidecar timeout_waiting_for_oi repeats under 0.1s budget; OI refresh cap repeats first symbols; Hyperliquid raw openInterest used as quote OI`

### Summary

The production question was not whether OI should fail closed. That business
semantic is correct: entry must not open when required OI evidence is missing.
The bug was that simple public OI data was being routed through an over-wide
and over-short data path, so V2 could manufacture persistent
`entry_market_evidence_block` samples even when the exchange offered cheap,
symbol-scoped public OI endpoints.

This closure changes only market-data evidence acquisition and diagnostics. It
does not relax quote TTL, OI floor, liquidity floor, entry ranking, post-only,
reduce-only, sizing, close, recovery, residual repair, or current-exposure
classification.

### Root Cause

- Binance/Aster candidate-scoped `fetch_entry_open_interest_evidence()` reused
  full `fetch_funding_tickers()`, which fetches full bookTicker, full
  premiumIndex, full 24hr volume, then per-symbol OI. A single candidate OI
  probe therefore inherited the sidecar full-universe path.
- The sidecar fast quote path uses a 0.1s OI enrichment budget, which is correct
  for quote publication but too short to decide a candidate-level OI refresh.
  Slow OI tasks were cancelled on timeout, so the existing 10 minute OI cache
  could never be warmed by those attempts.
- The OI refresh cap always selected the first slice of missing symbols. In a
  large universe, later symbols could remain `deferred_by_cap` across cycles
  even though the cap itself was intentional.
- Hyperliquid `metaAndAssetCtxs.openInterest` was treated as quote notional.
  It is base-size OI evidence and must be multiplied by `markPx`; if mark is
  unavailable the OI evidence is unavailable, not `available + raw base`.

### Fix

- Binance/Aster entry OI now uses dedicated single-symbol public calls:
  `premiumIndex?symbol=` for mark and `openInterest?symbol=` for OI, then
  computes `openInterest * markPrice` as quote-notional OI.
- Sidecar quote publication still uses the 0.1s fast path, but pending OI tasks
  are no longer cancelled. They are retained as bounded background inflight and
  write successful results into the existing 10 minute OI cache.
- Sidecar OI evidence now reports `refresh_inflight` while a slow background
  task is still running. Real timeouts, HTTP errors, rate limits, unsupported
  symbols, parse errors, and missing mark prices remain explicit evidence
  statuses.
- The 128 symbol refresh cap now rotates across cycles and reuses inflight/cache
  evidence, so the same first slice is not retried forever.
- Runtime candidate OI refresh now batches targets per venue through
  `refresh_open_interest_batch(venue, symbols)`, while preserving per-symbol
  journal events and fail-closed admission behavior.
- Hyperliquid OI is quote-normalized as `openInterest * markPx`; missing mark
  produces `unavailable/missing_mark_price`.

### Acceptance Semantics

- OI unavailable, timeout, refresh-inflight, HTTP/rate-limit, parse, and missing
  mark evidence remain entry admission blockers. They are not current exposure.
- Only confirmed `available` OI below the configured floor can be treated as
  below-floor/structural liquidity evidence.
- The fix reduces false admission blocking caused by the data path. It does not
  make opening or closing orders easier by changing thresholds or trading guards.

## Cluster CL-108 - Entry OI admission action taxonomy closure

| Status | Severity | Family | Modules | Files |
|---|---|---|---|---|
| local green; deploy pending | medium | entry OI evidence taxonomy, diagnose admission blocker naming, market-data semantic closure | business-contract, diagnose-live, bug-ledger | `lightfee/engine/business_contract.py`, `scripts/diagnose_live.py`, `tests/test_business_contract.py`, `tests/test_diagnose_live.py` |

### Fingerprint

`entry_market_evidence_summary action_counts block_oi_unavailable despite open_interest_evidence_status=available and confirmed OI below floor`

### Summary

Post-deploy production probes showed that OI fetching was healthy across the
candidate venues, but `entry_market_evidence_summary.action_counts` still used
`block_oi_unavailable` for every OI admission block. That made confirmed
available-but-below-floor OI look like a market-data retrieval failure.

This closure changes only shared diagnostic taxonomy. It does not relax quote
TTL, OI floor, liquidity floor, entry ranking, post-only, reduce-only, sizing,
close, recovery, or current-exposure classification.

### Fix

- `entry_market_evidence_contract(...)` now maps confirmed available
  `perp_open_interest_below_floor` to `block_oi_below_floor`.
- Confirmed available `perp_open_interest_structural` now maps to
  `block_oi_structural`.
- Real missing/timeout/rate-limit/unsupported/parse OI evidence continues to
  map to `block_oi_unavailable`.
- `diagnose_live` now exposes OI blocker sub-counts:
  `below_floor_count`, `structural_count`, and `unavailable_count`.
- When all OI blockers are confirmed low-OI evidence, diagnose reports
  `next_action=confirmed_oi_below_floor_no_data_backfill` instead of pointing
  operators at data-source backfill.

### Acceptance Semantics

- `block_oi_unavailable` means the OI evidence itself is not trustworthy enough
  to admit a candidate.
- `block_oi_below_floor` and `block_oi_structural` mean OI evidence is
  available and the candidate is blocked by the existing liquidity floor.
- All three remain entry admission blockers only. They do not become current
  exposure, current close blockers, or historical PnL facts.

### Local Verification

- RED proved available low-OI samples were previously collapsed into
  `block_oi_unavailable`.
- GREEN keeps unavailable OI fail-closed while separating below-floor and
  structural low-OI evidence in both the shared contract and diagnose summary.
