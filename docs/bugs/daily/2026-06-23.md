## Cluster CL-110 - Aster admission, close-artifact noise, lifecycle, and stale-quote diagnostics

| Status | Severity | Family | Modules | Files |
|---|---|---|---|---|
| local green; deploy pending | high | Aster max-notional admission diagnostics, passive-close artifact visibility, quote stale revalidate diagnostics, lifecycle mapping | venue-transport, market-data-runtime, diagnose-live, business-contract, lifecycle-closure | `lightfee/venues/transport.py`, `lightfee/engine/market_data_runtime.py`, `lightfee/engine/business_contract.py`, `lightfee/engine/v1_lifecycle_closure.py`, `scripts/diagnose_live.py` |

### Fingerprint

`runtime.entry_admission_blocked reason=max_notional_admission_blocked` without requested/remaining/gap evidence; Binance/Aster `-2022 ReduceOnly Order is rejected` or Bybit `110072 duplicate orderLinkId` appearing as current top errors after terminal flat truth; `reconciliation.pending_close_exchange_truth_refreshed` unmapped; `quote_stale` blockers without WS-BBO/REST revalidate source and terminal-stale bucket.

### Summary

The latest deployment review found the trading path itself was already safe, but
three diagnostic families were still too coarse for production operation:
Aster admission failures needed actionable headroom fields, close artifacts
needed stricter terminal identity rules before being downgraded to noise, and
stale quote evidence needed to say exactly whether WS-BBO lease or REST
revalidate resolved the blocker.

This closure changes diagnostics and evidence classification only. It does not
auto-resize Aster orders, does not bypass
`remainingOpenableNotionalValue`, does not relax quote TTL, OI floor,
liquidity floor, entry admission, sizing, order, close, recovery, or residual
repair guards.

### Root Cause

- Aster headroom admission events carried requested and remaining notional, but
  not the computed gap or per-symbol rollup/advice summary. Operators had to
  infer whether the block was account leverage, position limit, or capital
  configuration.
- Close artifact diagnostics had two layers. `order_error_evidence` already
  filtered resolved artifacts through trusted summaries, but
  `diagnostic_noise_summary` could still label a reduce-only close artifact as
  historical when exchange truth was clean even if no strong order/client
  identity matched terminal close evidence.
- `reconciliation.pending_close_exchange_truth_refreshed` was valid
  passive-close evidence but not mapped in the V1 lifecycle table.
- Stale quote revalidation paths did not consistently expose sidecar reason,
  WS-BBO lease hit, REST revalidate hit, or whether a REST result was still
  terminal stale. The legacy `refresh_quote(...)` fallback could return a
  fresh quote without leaving a REST-hit diagnostic flag.

### Fix

- Aster admission events now include `notional_gap`; diagnose reports
  requested notional, remaining openable notional, leverage, per-symbol top
  blockers, and an Aster configuration advice bucket.
- Reduce-only / zero-fill close artifacts now require same-order terminal
  identity before resolving as `reduce_only_terminal_flat` or
  `zero_fill_terminal_flat`. Dirty exchange truth, missing terminal state, or
  missing strong identity keeps the artifact as a current blocker.
- `diagnostic_noise_summary` now rechecks trusted truth-gap, terminal-zero-qty,
  and close-terminal summaries before historicalizing close artifacts. Bybit
  duplicate `110072` remains resolved only through the existing duplicate
  client/order-truth identity path.
- `reconciliation.pending_close_exchange_truth_refreshed` maps to
  `PASSIVE_CLOSE`.
- Quote revalidate diagnostics now report `sidecar_reason`,
  `ws_bbo_lease_hit`, `rest_revalidate_attempted`, `rest_revalidate_hit`, and
  `rest_revalidate_terminal_stale`. Fresh WS-BBO or REST revalidate removes the
  `quote_stale` blocker; REST results that are still stale remain fail-closed
  with precise buckets such as `rest_resolved_but_stale`.

### Acceptance Semantics

- Aster `max_notional_admission_blocked` remains fail-closed. The system does
  not shrink quantity or submit a one-sided smaller order.
- Stale quote remains an entry admission blocker unless fresh quote truth is
  proven by WS-BBO lease or REST revalidate.
- Close artifact downgrade requires terminal flat/no-open-order truth plus
  trusted identity. Unmatched errors remain current problems.

## Cluster CL-109 - Binance/Aster REST top-book transaction time vs lease freshness

| Status | Severity | Family | Modules | Files |
|---|---|---|---|---|
| local green; deploy pending | high | entry quote evidence, REST top-book freshness, lifecycle diagnostic closure | marketdata, entry-readiness, runtime-targeted-refresh, diagnose-live, lifecycle-closure | `lightfee/marketdata/ws_bbo.py`, `lightfee/engine/entry_readiness.py`, `lightfee/engine/market_data_runtime.py`, `scripts/diagnose_live.py`, `lightfee/engine/v1_lifecycle_closure.py` |

### Fingerprint

`runtime.entry_quote_revalidate_failed reason_bucket=rest_resolved_but_stale` after Binance/Aster `bookTicker` REST returned valid bid/ask; repeated `runtime.entry_quote_rewarm_scheduled_after_rest_stale` on low-activity Aster symbols such as XCNUSDT/GUNUSDT.

### Root Cause

V2 used Binance-style `bookTicker.time` as `TopBookQuote.observed_at_ms`, and
entry quote lease validation treats `observed_at_ms` as the system freshness
timestamp. Binance documents `time` on `/fapi/v1/ticker/bookTicker` as
transaction time. On low-activity symbols, transaction time can be older than
the quote lease while the REST response is still a current top-book snapshot,
so V2 incorrectly converted a successful REST refresh into
`rest_resolved_but_stale`.

### Fix

- `TopBookQuote.observed_at_ms` remains the quote lease freshness timestamp.
  Binance/Aster REST top-book refresh now sets it to local REST receipt time.
- `exchange_event_at_ms` records the exchange transaction/event timestamp for
  diagnostics, and `received_at_ms` remains the local response receipt time.
- Runtime and entry-readiness REST refresh evidence now include
  observed/received/exchange-event timestamps so post-deploy diagnose can
  distinguish stale transport from low transaction frequency.
- `reconciliation.pending_close_backfill_retained` is mapped to passive-close
  lifecycle evidence, closing the unrelated unmapped-event diagnostic gap.

### Acceptance Semantics

The fix does not relax quote TTL, OI floors, liquidity floors, ranking, sizing,
order submission, close, recovery, or residual repair. REST top-book still
fails closed for HTTP/parse/timeout/unsupported symbols and invalid bid/ask.

## Cluster CL-107 - Entry OI market-data root fix after admission blockers

| Status | Severity | Family | Modules | Files |
|---|---|---|---|---|
| local green; deploy pending | high | entry OI evidence, sidecar slow enrichment, market-data admission blockers, Hyperliquid OI normalization | market-data-client, sidecar, runtime-targeted-refresh, bug-ledger | `lightfee/venues/market_data.py`, `lightfee/engine/market_data_runtime.py`, `tests/venues/test_market_data_client.py`, `tests/test_runtime_snapshot_freshness.py`, `tests/sidecar/test_sources.py` |

### Fingerprint

`entry_market_evidence_block OI unavailable; Binance/Aster entry OI reuses full fetch_funding_tickers; sidecar timeout_waiting_for_oi repeats under 0.1s budget; OI refresh cap repeats first symbols; Hyperliquid raw openInterest used as quote OI`

### Summary

The production question was not whether OI should fail closed. That business
semantic is correct: entry must not open when required OI evidence is missing.
The bug was that simple public OI data was being routed through an over-wide
and over-short data path, so V2 could manufacture persistent
`entry_market_evidence_block` samples even when the exchange offered cheap,
symbol-scoped public OI endpoints.

This closure changes only market-data evidence acquisition and diagnostics. It
does not relax quote TTL, OI floor, liquidity floor, entry ranking, post-only,
reduce-only, sizing, close, recovery, residual repair, or current-exposure
classification.

### Root Cause

- Binance/Aster candidate-scoped `fetch_entry_open_interest_evidence()` reused
  full `fetch_funding_tickers()`, which fetches full bookTicker, full
  premiumIndex, full 24hr volume, then per-symbol OI. A single candidate OI
  probe therefore inherited the sidecar full-universe path.
- The sidecar fast quote path uses a 0.1s OI enrichment budget, which is correct
  for quote publication but too short to decide a candidate-level OI refresh.
  Slow OI tasks were cancelled on timeout, so the existing 10 minute OI cache
  could never be warmed by those attempts.
- The OI refresh cap always selected the first slice of missing symbols. In a
  large universe, later symbols could remain `deferred_by_cap` across cycles
  even though the cap itself was intentional.
- Hyperliquid `metaAndAssetCtxs.openInterest` was treated as quote notional.
  It is base-size OI evidence and must be multiplied by `markPx`; if mark is
  unavailable the OI evidence is unavailable, not `available + raw base`.

### Fix

- Binance/Aster entry OI now uses dedicated single-symbol public calls:
  `premiumIndex?symbol=` for mark and `openInterest?symbol=` for OI, then
  computes `openInterest * markPrice` as quote-notional OI.
- Sidecar quote publication still uses the 0.1s fast path, but pending OI tasks
  are no longer cancelled. They are retained as bounded background inflight and
  write successful results into the existing 10 minute OI cache.
- Sidecar OI evidence now reports `refresh_inflight` while a slow background
  task is still running. Real timeouts, HTTP errors, rate limits, unsupported
  symbols, parse errors, and missing mark prices remain explicit evidence
  statuses.
- The 128 symbol refresh cap now rotates across cycles and reuses inflight/cache
  evidence, so the same first slice is not retried forever.
- Runtime candidate OI refresh now batches targets per venue through
  `refresh_open_interest_batch(venue, symbols)`, while preserving per-symbol
  journal events and fail-closed admission behavior.
- Hyperliquid OI is quote-normalized as `openInterest * markPx`; missing mark
  produces `unavailable/missing_mark_price`.

### Acceptance Semantics

- OI unavailable, timeout, refresh-inflight, HTTP/rate-limit, parse, and missing
  mark evidence remain entry admission blockers. They are not current exposure.
- Only confirmed `available` OI below the configured floor can be treated as
  below-floor/structural liquidity evidence.
- The fix reduces false admission blocking caused by the data path. It does not
  make opening or closing orders easier by changing thresholds or trading guards.

### Verification

- RED/GREEN coverage proves Binance/Aster entry OI calls only single-symbol
  `premiumIndex` and `openInterest`, not full bookTicker or 24hr endpoints.
- RED/GREEN coverage proves slow sidecar OI first publishes quote evidence with
  `refresh_inflight`, then warms background cache without repeat timeout.
- RED/GREEN coverage proves OI refresh cap rotation reaches later symbols.
- RED/GREEN coverage proves runtime targeted refresh batches same-venue symbols
  and still writes per-symbol resolved/failed journal records.
- RED/GREEN coverage proves Hyperliquid OI is quote-normalized.

## Cluster CL-108 - Entry OI admission action taxonomy closure

| Status | Severity | Family | Modules | Files |
|---|---|---|---|---|
| local green; deploy pending | medium | entry OI evidence taxonomy, diagnose admission blocker naming, market-data semantic closure | business-contract, diagnose-live, bug-ledger | `lightfee/engine/business_contract.py`, `scripts/diagnose_live.py`, `tests/test_business_contract.py`, `tests/test_diagnose_live.py` |

### Fingerprint

`entry_market_evidence_summary action_counts block_oi_unavailable despite open_interest_evidence_status=available and confirmed OI below floor`

### Summary

Post-deploy production probes showed that OI fetching was healthy across the
candidate venues, but `entry_market_evidence_summary.action_counts` still used
`block_oi_unavailable` for every OI admission block. That made confirmed
available-but-below-floor OI look like a market-data retrieval failure.

This closure changes only shared diagnostic taxonomy. It does not relax quote
TTL, OI floor, liquidity floor, entry ranking, post-only, reduce-only, sizing,
close, recovery, or current-exposure classification.

### Fix

- `entry_market_evidence_contract(...)` now maps confirmed available
  `perp_open_interest_below_floor` to `block_oi_below_floor`.
- Confirmed available `perp_open_interest_structural` now maps to
  `block_oi_structural`.
- Real missing/timeout/rate-limit/unsupported/parse OI evidence continues to
  map to `block_oi_unavailable`.
- `diagnose_live` now exposes OI blocker sub-counts:
  `below_floor_count`, `structural_count`, and `unavailable_count`.
- When all OI blockers are confirmed low-OI evidence, diagnose reports
  `next_action=confirmed_oi_below_floor_no_data_backfill` instead of pointing
  operators at data-source backfill.

### Acceptance Semantics

- `block_oi_unavailable` means the OI evidence itself is not trustworthy enough
  to admit a candidate.
- `block_oi_below_floor` and `block_oi_structural` mean OI evidence is
  available and the candidate is blocked by the existing liquidity floor.
- All three remain entry admission blockers only. They do not become current
  exposure, current close blockers, or historical PnL facts.

### Local Verification

- RED proved available low-OI samples were previously collapsed into
  `block_oi_unavailable`.
- GREEN keeps unavailable OI fail-closed while separating below-floor and
  structural low-OI evidence in both the shared contract and diagnose summary.
