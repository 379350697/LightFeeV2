## Cluster CL-125: OKX funding fanout aggregate cancellation

### GitNexus Keys

- Fingerprint: `okx-funding-fanout-aggregate-cancellation`
- Components: `market-data`, `sidecar-snapshot`, `production-observability`
- Symbols: `MarketDataClient._fetch_okx_style`, `MarketDataClient.fetch_funding_tickers`
- Files: `lightfee/venues/market_data.py`, `tests/venues/test_market_data_client.py`
- Commits causing regression: `336ad5f8`, `fd1579d6`
- Watch: sidecar FD count, `CLOSE_WAIT`, `runtime.snapshot_degraded`, OKX source age, `quote_stale`
- Card: [market-data-snapshot-freshness](../cards/market-data-snapshot-freshness.md)

### Symptom and Production Evidence

The 2026-08-26 production audit found no live position or open-order anomaly,
but the sidecar held 41 `CLOSE_WAIT` sockets: 36 mapped to `www.okx.com:443`
and four to Aster. The latest OKX quote/funding snapshot was about 2.4 hours
old, repeatedly emitted `runtime.snapshot_degraded`, and all related candidates
were safely blocked as `quote_stale`. This made current opening availability
abnormal without permitting a stale-price entry.

### Authoritative Contract

V1 `OkxLiveAdapter::collect_okx_bulk_funding_by_symbol` uses
`OKX_BULK_FUNDING_REST_FALLBACK_LIMIT = 4`: a multi-symbol cold cache makes at
most four funding REST fallbacks and each request completes through the normal
client lifecycle. V2 may preserve its bulk ticker and in-memory cache, but it
must preserve that bounded request lifecycle. A complete quote with missing or
stale funding remains insufficient for entry; it may not be converted into a
safe funding value.

### Root Cause and Missed Coverage

`336ad5f8` widened V2 cold-cache funding fanout to 40 while retaining only a
partial V1 cache comparison. `fd1579d6` then wrapped the whole batch in a 0.2s
`wait_for` to keep the quote snapshot fast. The individual requests allowed six
seconds, but the enclosing budget canceled them after 0.2s once sockets were
already open. Awaiting canceled asyncio tasks did not guarantee the HTTP
transport had released the peer-closed sockets, producing the observed
`CLOSE_WAIT` accumulation.

The former regression only asserted that bid/ask returned quickly after slow
funding was canceled. It did not use the `fetch_funding_tickers` production
path, count transport starts, distinguish completion from cancellation, or
assert V1's four-request contract. It therefore preserved the regression.

### Rejected Repair Direction

Do not restore the old fast path by increasing request concurrency, shortening
an aggregate batch deadline, or canceling in-flight HTTP work after it has
opened a connection. Do not blindly revert the two commits either: their symbol
normalization and funding-cache repairs remain required. New public WebSocket
or generic queue infrastructure is out of scope because the existing market
data client owns the required boundary.

### Fix

The shared OKX market-data boundary now selects at most four stale/missing
funding symbols, rotates that bounded set across cache misses, and awaits those
requests to their normal response or individual timeout. The only cancellation
remaining is service/outer-lifecycle cancellation, whose `finally` cancels and
awaits every child before exit. Quote rows still publish if a selected funding
request fails, but their funding evidence remains unavailable and entry stays
fail-closed.

### Counterexample Matrix

| Case | Required outcome | Regression coverage |
|---|---|---|
| Eight cold symbols, successful funding | at most four requests; quote rows remain available | bounded-concurrency regression |
| Sixty-four cold symbols, repeated refresh | all cache misses eventually receive funding; no symbol starvation | large-universe rotation regression |
| Slow real `httpx` funding handler | exactly four starts, four normal completions, zero cancellations | production-path slow-transport regression |
| Partial funding transport failure | bid/ask stays available; failed symbol funding stays unavailable | partial-failure regression |
| Service/outer cancellation | all owned child tasks are canceled and awaited | explicit `finally` ownership path; deployment FD watch remains required |

### Verification

The RED proof on the pre-fix code showed eight starts for eight cold symbols
and, with 64 slow `httpx` requests, 40 starts followed by 40 cancellations at
the 0.2s aggregate deadline. The fixed production-path matrix proves four
normal slow-request completions with zero ordinary cancellations and four
awaited child cancellations when the parent refresh is canceled. Targeted
venue tests plus health/diagnosis selection (`223 passed`), close/accounting
selection (`349 passed`), and the full validation profile (10/10 steps) are
green locally. Deployment observation remains required before closure.

### Acceptance

Deployed in `dc83dc7` on 2026-08-27. The first post-restart sample has a fresh
seven-venue source snapshot, sidecar FD `14`/`CLOSE_WAIT=0`, and live FD
`20`/`CLOSE_WAIT=0`; it is therefore evidence the fanout leak is absent at
startup. It is not closure: a second no-growth observation and the normal
deployment acceptance remain pending while remote SSH is intermittently
unavailable.
