## Cluster CL-086: Quote REST invalid-quote diagnostics and OI cap/timeout evidence

### GitNexus Keys

- Fingerprint:
  `quote-rest-invalid-quote-diagnostic-split + oi-evidence-cap-timeout-observability`
- Components:
  `entry-quote-truth`, `market-data`, `sidecar-snapshot`, `entry-liquidity`,
  `diagnose-live`, `offline-analysis`, `production-observability`
- Watch:
  `runtime.entry_quote_revalidate_failed.reason_bucket`,
  `runtime.entry_quote_revalidate_failed.reason_family`,
  `runtime.entry_quote_revalidate_failed.quote_validation_reject_reason`,
  `execution.entry_liquidity_blocked.open_interest_evidence_reason`,
  `execution.entry_liquidity_blocked.oi_*`,
  `entry_outcome_summary.quote_lease_failure_family_counts`,
  `entry_outcome_summary.oi_liquidity_health_summary`

### Summary

This is a follow-up to CL-085. The deployed system was flat/no-open-orders and
had no current order errors, but the remaining no-entry attribution still had
diagnostic ambiguity. A failed REST top-book fallback could be recorded as a
generic `rest_invalid_quote` whether the exchange quote was stale, missing a
timestamp, invalid bid/ask, unsupported, HTTP/parse failed, or timed out. OI
blocks could show `deferred_by_cap` or `timeout` without enough cache/cap/timing
context to decide whether a later throughput optimization is justified.

### Root Cause

V2 is correctly using WS-BBO quote leases instead of restoring V1 local L2, and
V1 semantics still require fresh execution top-book truth before entry. The
implementation already failed closed, but the diagnostic shape was not
decision-complete. For OI, Binance officially exposes per-symbol
`openInterest`, while Aster has no confirmed bulk V3 OI endpoint in the
referenced docs; therefore the right implementation is cache/cap evidence, not
full-universe per-symbol hot-path requests.

### Fix

- REST quote revalidation now records precise failure buckets:
  `rest_resolved_but_stale`, `rest_resolved_missing_observed_at`,
  `rest_resolved_invalid_bid_ask`, `rest_unsupported_symbol`,
  `rest_http_error`, `rest_parse_error`, and `rest_timeout_or_exception`.
- Failed REST quote events preserve compatibility with
  `reason_family=rest_invalid_quote` and add reject reason, observed timestamp,
  age, bid, and ask evidence.
- Binance/Aster-style OI enrichment now emits cache hit/miss, refresh cap,
  refresh attempts, deferred count, timeout count, and elapsed time as read-only
  evidence on funding tickers, sidecar quotes, and entry liquidity blockers.
- `diagnose_live` and offline blocker analysis aggregate quote precise buckets,
  quote family buckets, OI evidence reasons, and OI cache/cap/timeout health
  separately from strategy/admission/order errors.

### Non-Changes

- No quote stale, OI/liquidity, admission, sizing, order submit, close,
  recovery, or lifecycle guard was loosened.
- No exchange execution abstraction was unified. Exchange-specific data access
  remains venue-specific; only the business evidence contract is unified.
- No full-universe per-symbol OI request path was introduced.

## Cluster CL-087: WS-BBO sticky warm and candidate-scoped OI targeted refresh

### GitNexus Keys

- Fingerprint:
  `ws-bbo-sticky-warm + candidate-scoped-oi-targeted-refresh`
- Components:
  `entry-quote-truth`, `ws-bbo`, `market-data`, `entry-liquidity`,
  `diagnose-live`, `offline-analysis`
- Watch:
  `runtime.entry_oi_targeted_refresh_started`,
  `runtime.entry_oi_targeted_refresh_resolved`,
  `runtime.entry_oi_targeted_refresh_failed`,
  `entry_outcome_summary.oi_targeted_refresh_summary`,
  `runtime.entry_quote_revalidate_failed.reason_bucket`,
  `runtime.entry_ws_bbo_top_candidate_rewarm_*`

### Summary

Production after CL-086 was operationally healthy but still showed that real
entry opportunities could be blocked by two code-path issues rather than by
risk intent: WS-BBO targets could cold-start between scans, and Binance/Aster
OI evidence inherited full-universe sidecar cap/timeout results even when a
finalist only needed two venue+symbol facts. This fix keeps all hard risk
constraints intact and repairs the evidence path.

### Root Cause

V2 intentionally replaced V1 local L2 with WS-BBO quote lease, but the warm
scope was too transient for finalist readiness. For OI, V1 semantics are
candidate-demand evidence; Binance official OI is per-symbol and Aster has no
confirmed reliable bulk V3 OI path, so full-universe enrichment must not be the
only path that can satisfy a finalist liquidity gate. Real public endpoint
smoke added one more concrete root cause: the sidecar enrichment budget is
intentionally 100ms so quote/funding publication stays fast, but Binance/Aster
candidate OI public calls were observed around 354-368ms for BTC/ETH. Reusing
the sidecar 100ms budget for entry-targeted refresh would deterministically
misclassify valid candidate OI as `timeout`.

### Fix

- WS-BBO entry warmup now keeps a short sticky warm set. Current candidate
  targets remain first in budget; recent targets are appended only within the
  same per-venue budget and freshness contract.
- `MarketDataClient.fetch_entry_open_interest_evidence()` refreshes only the
  requested candidate symbols through the existing public exchange data path.
- Entry-targeted OI refresh now uses a separate bounded public-data budget
  instead of reusing the sidecar 100ms enrichment budget. The sidecar fast path
  remains unchanged.
- Runtime calls targeted OI refresh before the snapshot freshness/liquidity
  filter. Available targeted evidence patches only OI fields on the current
  quote; stale quote, OI floor, admission, sizing, and order gates remain
  unchanged.
- `diagnose_live` and offline blocker analysis now separate sidecar OI cap
  pressure from entry targeted refresh outcomes.

### Non-Changes

- No quote stale TTL was increased or bypassed.
- No OI floor, liquidity threshold, admission, sizing, order, close, recovery,
  or lifecycle guard was loosened.
- No global full-universe OI cap was raised.
- No exchange execution abstraction was unified.

### Verification

Local focused RED/GREEN verification has passed for:

- candidate-scoped Binance OI refresh after full-universe cap deferral;
- runtime targeted OI refresh success before liquidity gate;
- targeted OI timeout remaining fail-closed;
- WS-BBO sticky warm set retaining a previous target;
- diagnose and offline analysis targeted OI summaries.
- real public smoke for Binance/Aster `BTCUSDT`/`ETHUSDT` candidate-scoped OI:
  bid/ask valid, 24h volume positive, OI quote positive, status `available`,
  no `deferred_by_cap`, and no `timeout` under the entry-targeted budget.
