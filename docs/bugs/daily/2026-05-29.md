### V1 Comparison

This is the same root family as `BEATUSDT`/`OPGUSDT` rather than a new strategy issue.

- V1 does not repeat an identical terminal under-minimum hedge forever. It buffers while the maker can still accumulate; once maker terminality or attempt exhaustion is reached, it emits the min-notional abort path and compensates/flattens from live exchange truth.
- V1 residual repair is driven as normal housekeeping for non-paused tasks. It computes live excess on the repair venue and either sends a reduce-only repair, terminalizes official dust, or stays fail-closed when live truth is untrusted. V1 remains conservative once a task is locally paused; V2 therefore needs an explicit root-fix extension for production PARTI, guarded by trusted live position/open-order truth and retry backoff.
- V2 drift:
  - `PassiveCloseExecutor._flatten_live_one_sided_position()` treats `price_unavailable_for_min_notional` as a retryable 5-second delay even with confirmed one-sided live exposure.
  - `Runtime._recover_residual_repairs()` refuses to submit a tradeable repair when a task is already locally paused or attempt-exhausted, leaving `residual_repair_live_position_nonzero` as a permanent gate.

### Root Fix Required

1. Preserve live-flat truth priority.
2. For live one-sided passive close with missing price evidence, stop the retry loop and route through V1-style live-truth compensation/flattening. If compensation cannot prove flat, stay fail-closed with structured evidence.
3. For residual repair with trusted live nonzero repair-venue excess, submit reduce-only IOC even when the task is paused or attempts are exhausted, but preserve retry backoff after submit failures.
4. When no local open position remains and the repair venue live side contradicts the stale task side, rebuild the close side from signed live truth before submit. This is an OKX/venue-doc-supported V2 root fix, not a pure V1 replay.
5. If residual live excess is official dust, terminalize and release the gate.
6. If exchange truth or open-order truth is unavailable, keep fail-closed with a non-empty structured reason.
7. Add 2026-05-29 harness coverage for both `JCTUSDT` and `PARTIUSDT`.
8. Add or preserve read-only probe coverage proving probe files do not mutate exchange state and real probes remain explicitly gated.

### Fix Status

Fixed locally in this worktree.

- `PassiveCloseExecutor._flatten_live_one_sided_position()` no longer treats `price_unavailable_for_min_notional` as a retryable loop for confirmed live one-sided exposure. It emits the dust diagnostic, then routes through V1-style live-truth compensation/flattening with source `fallback_live_one_sided_price_unavailable`.
- The same terminal price-unavailable rule is applied to live-imbalanced excess exposure with source `fallback_live_imbalanced_price_unavailable`.
- `Runtime._recover_residual_repairs()` no longer pauses tradeable live excess solely because the residual task is locally paused or attempt/deadline exhausted. When live truth is trusted and the excess is tradeable, it resumes and submits the reduce-only IOC repair.
- Repeated residual submit failures now remain paused with `next_attempt_ms` backoff, so the PARTI resume path cannot become a housekeeping-tick order storm.
- If a stale no-local-position task has the wrong close side, the repair side is rebuilt from signed live truth before submit. Production PARTI's OKX short `50.0` therefore maps to `BUY reduceOnly`/short close semantics.
- Residual repair failures now preserve the actual last error and include `live_excess_quantity`, `baseline_quantity`, `live_size`, and `open_order_count` in the failure event for root-cause evidence.
- Existing residual tests were corrected so V1 semantics are explicit: tradeable live nonzero repairs; untrusted open-order/position truth remains fail-closed.
