### WT-20260904-1 — matched live pair was kept in `risk_only`

**Evidence and contract.** A TUSDT pair matched Binance/Bybit account truth,
but a stale risk-only latch remained because V2 treated every local open
position as recovery work. V1 permits a matched live pair to be checked against
complete account truth; only pending entries/closes, residual repairs, or
reservations require the recovery gate.

**Repair.** The existing account-truth refresh owner now runs for a matched open
pair, bounded by the private-position probe interval. It clears the latch only
after both account positions and open orders are complete and matching; partial
or unavailable truth still retains `risk_only/fail_closed`.

**Regression.** A runtime-path test covers block → complete paired truth →
`running`, including the interval guard. Existing incomplete-truth and
terminal-flat cases remain green. A deployed observation is still required.

### WT-20260904-2 — Bitget contract precision was guessed from static defaults

**Evidence and contract.** Production returned Bitget `40020` for a low-price
TUSDT order. The old builder formatted `0.0044` as `0.00`; V1 and Bitget's
contract catalog require the exchange precision and quantity contract. The
shared rule owner now reads
`/api/v2/mix/market/contracts` (`productType=USDT-FUTURES`), parses
`priceEndStep`/`pricePlace`, `sizeMultiplier`/`volumePlace`, and
`minTradeNum`, and refuses live submission when authoritative rules are
missing or malformed. Classic and UTA adapter paths use the same preflight and
decimal wire formatter for maker and taker orders; zero-valued decimal-place
counts are accepted because they are valid integer-price/integer-size catalog
values.

**Regression.** Catalog parsing, malformed fallback, Classic/UTA wire bodies,
and the live Classic adapter path preserve `0.0044` instead of `0.00`.
No retry or alternate precision source was added. Production must observe a
natural eligible low-price candidate; no forced order is allowed.

### WT-20260904-3 — Bitget literal heartbeat was decoded as JSON

**Evidence and contract.** Bitget Local-L2 can send literal `ping`/`pong`.
V2 attempted JSON decoding first and recorded a decode error. The parser now
handles the control frame before JSON while retaining the existing keepalive
and transport diagnostics.

**Regression.** Text and bytes `ping`/`pong` produce keepalive events and no
decode error. No heartbeat loop or reconnect policy was changed.
