### Summary

Production showed a false-green state: both live and sidecar processes were active, but sidecar was not publishing production-quality opportunity input and live remained blocked by historical fail-closed state.

The immediate production hotfix was operational:

- sidecar systemd was overridden to pass the live sidecar config explicitly.
- system resolver order was changed so `www.okx.com` resolves.
- live persisted state was backed up and stale `fail_closed` was cleared only after open/pending work was verified as zero.

This restored business health, but it does not yet prevent recurrence after reboot, NetworkManager rewrite, redeploy, or a future clean-start fail-closed latch.

### Shared Root Cause

Production health was inferred from process liveness instead of business invariants. The system lacked a versioned deployment contract and automated checker for:

- sidecar command/config path,
- 7 venue live snapshot coverage,
- resolver health,
- live risk-mode/current-state semantics,
- safe recovery from stale persisted fail-closed state.

### Issue CL-002-A: OKX Funding Missing in Large Universe

#### Fingerprint

`okx.funding_rate.zero_coverage.large_universe`

#### Root Cause

OKX quotes are present through the ticker/open-interest path, but the large-universe funding enrichment path does not populate funding rates. The previous safety fix prevented slow per-symbol funding calls from dragging the whole sidecar, but it left OKX funding coverage at zero in production.

#### Failed / Ineffective Attempts

Checking only venue count, quote count, and degraded venue count was ineffective. OKX appeared healthy because it produced quote rows, while its funding fields were unusable for V1-style funding-edge ranking.

#### Fix Status

Fixed in `631dc5e` + `647da1e`:

1. **Field name**: `fundingTime` → `nextFundingTime` for V1 parity
2. **50-symbol cap removed**: OKX's full 620-symbol universe can now be fetched
3. **Funding cache**: 10-min TTL matching V1 `OKX_FUNDING_CACHE_MAX_OBSERVED_AGE_MS` (dual freshness: `funding_ts > now + 30s` AND `observed < 10min`). Eliminates 620 per-symbol REST calls after first warm cycle
4. **Concurrency + timeout**: 40 concurrent (was 20), 6s per-symbol (was 4s)
5. **Funding timeout**: 30s (was 10s) for cold-cache warm
6. **1000 prefix stripping**: OKX drops `1000`/`1000000` prefix from contract names (e.g. `BONK-USDT-SWAP`, not `1000BONK-USDT-SWAP`)
7. **Skip non-listed symbols**: symbols not in ticker are not listed on OKX — skip instead of creating zero-valued quote rows

Result: OKX 299/299 = 100% coverage (was 48%). `snapshot_degraded` no longer emitted for OKX.

### Issue CL-002-C: Funding Timestamp Missing Across All Venues

#### Fingerprint

`funding_timestamp_ms.zero_all_venues`

#### Root Cause

The V2 sidecar snapshot does not currently guarantee a usable funding timestamp. Some exchanges may not return explicit next funding timestamps in the quote endpoint, but V1-style candidate timing and prewarm semantics require a nonzero timestamp or a clearly documented fallback.

#### Failed / Ineffective Attempts

Relying on `published_at_ms` and `market_observed_at_ms` alone was insufficient. Those fields prove snapshot freshness, not funding event timing.

#### Fix Status

Fixed in `631dc5e`. Root cause was per-venue field-name mismatches vs V1 Rust production code:

| Venue | V2 (before) | V1 (correct) | Fix |
|-------|------------|-------------|-----|
| Binance/Aster | `lastFundingTime` (does not exist) | `nextFundingTime` | `nextFundingTime` |
| OKX | `fundingTime` | `nextFundingTime` | `nextFundingTime` |
| Bybit | hardcoded `0` | `nextFundingTime` | `nextFundingTime` |
| Hyperliquid | hardcoded `0` | `next_hour_boundary()` | `_next_hour_boundary()` |
| Bitget | `nextFundTime` (does not exist) | WS-only (REST unavailable) | `_now_ms()` fallback |
| Gate | `funding_next_apply` (does not exist) | WS-only (REST unavailable) | `_now_ms()` fallback |

Bitget and Gate REST ticker endpoints do not include funding time fields; V1 gets them via WebSocket. Using `_now_ms()` as documented fallback.
