### Summary

Focused V1/V2 close parity review found a new passive-close state-machine branch, not the same old LYN/GMT/ALT/OKX error-code issue copied verbatim. The full close parity matrix is tracked separately in `docs/parity/2026-05-25-v1-v2-close-parity-matrix.md`; this cluster only claims the UBUSDT/Bybit min-quantity branch and its direct recovery sweep.

- CL-001 on 2026-05-24 covered Bybit duplicate `orderLinkId` hedge reconciliation and stale local flat cleanup for LYNUSDT.
- CL-002 on 2026-05-23 covered recovered terminal-flat pending passive close snapshot fallback for GMTUSDT/LYNUSDT.
- CL-001 on 2026-05-23 covered Bybit sub-cent passive maker tick metadata for ALTUSDT.
- CL-003 on 2026-05-24 covered OKX contract-unit and residual-repair drift.

This branch is different: a tiny maker fill can become terminal `FILLED`, leaving a hedge delta that is below Bybit dynamic `minOrderQty` / `qtyStep`. V1 normalizes the hedge quantity first, checks min-notional/dust on that normalized quantity, and either accumulates, aborts/compensates, or clears live-flat state before any exchange submit. Baseline V2 submitted a `quantity=1.0` Bybit reduce-only hedge and received `retCode=10001`.

### V1 Comparison

- `exit.rs:2197-2313`: after maker progress, V1 computes `outstanding_hedge_quantity`, resolves buffer state, calls `adapter.normalize_quantity(...)`, then evaluates `close_leg_exchange_min_notional_violation(...)`.
- `exit.rs:2343-2414`: terminal maker `FILLED` does not bypass the min-notional accumulation/abort branch.
- `recovery.rs:2785-2901`: pending passive closes are continuously probed for live-flat state; if both venues are flat, V1 removes pending/open local state, logs `recovery.flat`, records drift, clears matching `last_error`, syncs runtime state, and persists.
- `live/bybit.rs:2099-2110` and `2896-2899`: Bybit order placement and normalization use exchange symbol metadata before submit.

### Fix Status

Fixed locally in the worktree and deployed as `local_patch_73d5428-reviewgap-20260525`.

- `_submit_hedge_for_delta()` now normalizes via `adapter.normalize_quantity()` before building the IOC request.
- Terminal maker `FILLED` calls `_submit_hedge_for_delta(..., maker_terminal=True)`, so it reaches the same normalized dust/min-quantity guard as non-terminal delta hedges.
- Dust/min-quantity rejection emits `exit.passive_close_hedge_dust_aborted`, probes live flatness, and avoids sending the under-min Bybit order.
- `process_pending_passive_closes()` now runs a V1-style live-flat sweep before driving a pending passive close.
- The local REVIEW GAP closure adds V1-equivalent live-flat recovery payload fields, clears matching `state.last_error`, and proves current-state/runtime and raw persistent-state views no longer retain the flat position.
- Bybit `VenueTransport.place_order()` and `normalize_quantity()` consult dynamic `SymbolRulesCache`, so real transport tests reject UBUSDT `quantity=1.0` before HTTP submit.

- `diagnose_live.py` now derives exchange-truth venues from local open positions and can instantiate Aster and OKX read-only adapters. For XCNUSDT, the intended read-only pair is Bybit/Aster, not Binance/Bybit.
