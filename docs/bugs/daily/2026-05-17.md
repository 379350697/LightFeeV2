#### Failed / Ineffective Attempts

- Filled hedges call `_finalize_pending_entry()`, emit `entry.opened` and `runtime.position_opened`, and remove the pending entry.
- Both long-maker and short-maker directions were directly reproduced.

### Issue CL-001-B: Hedge Inflight CID Was Not Stable or Venue-Legal

#### Fingerprint

`production.hedge-inflight-cid.invalid-or-not-reconciled`

#### Root Cause

The hedge submit path originally generated a raw CID from `entry_id` and timestamp. For real production entry IDs this could exceed venue constraints. After an uncertain hedge submit, the next reconcile pass also needed to query the same inflight CID; using the old hedge client order id would leave the submitted hedge untraceable and could allow duplicate hedge submission pressure.

#### Failed / Ineffective Attempts

Checking only that `hedge_inflight` exists was insufficient. The CID also had to be valid for the target venue, written to both `hedge_client_order_id` and `hedge_inflight`, retained on `UNCERTAIN`, cleared only on confirmed reject/fill, and used by subsequent reconcile calls.

#### Fix Status

Fixed in `7792db5`.

- Hedge CIDs use `generate_exchange_cid(entry_id, "h", hedge_venue)`.
- `_reconcile_pending_state()` and force reconcile prefer `pending.hedge_inflight or pending.hedge_client_order_id`.
- Uncertain submit retains inflight evidence; reject clears it.
- Duplicate submit is blocked while `hedge_inflight` is set.

### Issue CL-002-A: Primary Tracking Selection Mismatch

#### Fingerprint

`production.entry-local-l2.primary-tracking-selection-mismatch`

#### Root Cause

`LiveRuntime._entry_local_l2_selection_blocker()` checks whether each tradeable candidate is present in `_tracked_primary_pair_ids`. The runtime only tracks a bounded primary set, so many tradeable candidates are expected to be outside that set. Counting those candidates as `entry_local_l2_waiting_for_primary_tracking` makes true local-L2 readiness failures harder to see and can keep `selected_candidate_count=0` opaque.

#### Failed / Ineffective Attempts

Treating the frequency count as a pure venue-data problem is ineffective. This blocker occurs before exchange submission and before per-leg book readiness can be judged for untracked candidates.

#### Fix Status

**Local root-fix implemented.** Code changes:
- `LiveRuntime._select_entry_candidates()` accepts `admission_blocker_counts` separated from `selection_blocker_counts`; `entry_local_l2_waiting_for_primary_tracking` counted in admission bucket.
- `LiveRuntime._emit_scan_no_entry_diagnostics()` includes `selection_bucket_counts` with `not_primary_tracked` and `primary_tracked_not_ready`.
- `LiveRuntime._last_no_entry_diagnostics` stored for test assertions.
- No change to safety gate behavior: untracked candidates are still blocked, just counted separately.

### Issue CL-002-C: Pending/Reconcile Reaches Exchange Residual Constraints

#### Fingerprint

`production.pending-entry.reconcile-uncertain-and-hedge-residual`

#### Failed / Ineffective Attempts

- `LiveRuntime._venue_min_notional()` added: reads `min_notional` from venue spec.
- `_drive_missing_hedge_live()`: checks `repair_state` (skip if set), checks `hedge_notional < min_notional` → sets `repair_state = "hedge_residual_below_min_notional"`, journals event, returns False without retrying.
