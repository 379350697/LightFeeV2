### Production Symptom

The HOME evidence looked contradictory: local/pending state had matched positive
maker and hedge quantities, while current exchange truth did not show a matched
pair. OKX was flat, and Bybit carried the remaining single short exposure. This
cannot be summarized as a normal open/close bug or as only "maker succeeded,
hedge failed". The root problem is that local order evidence and live account
truth disagreed, and the live single leg needed an owner and cleanup path
instead of drifting as a generic orphan.

### Root Cause

The recurrence had three coupled roots:

1. Venue fill evidence was too weak in some paths. OKX order detail
   `accFillSz/fillSz` is cumulative order-detail evidence, not final fill truth.
   It must be cross-checked through `/api/v5/trade/fills` and converted from
   contracts to base with `ctVal`. A detail row with positive `accFillSz` but
   empty fills, especially while live position is flat, is an evidence gap.
2. Hedge/market ACK was still semantically dangerous. Bybit market orders are
   IOC-style and ACK only means accepted; executions must be reconciled through
   `/v5/execution/list`. Binance default ACK and other venue ACK-only paths have
   the same risk class: accepted is not filled.
3. Owner governance stopped too early. A pending entry with positive fill
   evidence can temporarily own a live single leg, but that ownership must not
   downgrade the artifact to ordinary owned work. It must block all new entry
   risk, route to flatten/block cleanup, and release only after account flat
   plus open-order truth is available.

### Fix

- OKX order reconciliation now queries `/api/v5/trade/order` or
  `/api/v5/trade/orders-history` only to resolve `ordId/clOrdId/state`, then
  queries `/api/v5/trade/fills` and only aggregates actual fills into
  `OrderFillReconciliation`. Empty fills record
  `detail_found;fills_empty`, `execution_not_found`, and
  `next_action=check_live_position`; they do not terminalize `entry.opened`.
- OKX fill and passive-progress quantities now convert contracts to base with
  `ctVal`; missing `ctVal` makes passive progress an evidence gap instead of a
  trusted base quantity.
- Bybit reconciliation remains execution-list based: order id/client id
  resolution is only an input to `/v5/execution/list`; empty executions return
  no fill. ACK-only market/IOC evidence cannot count as hedge filled.
- Bitget positive fill with missing or invalid side now fails closed with
  `REQUEST_REJECTED` instead of defaulting positive quantity to `buy`.
- Pending positive-fill entries are indexed by expected live leg owner keys.
  If exchange truth reports a live position owned by a pending entry, the ledger
  creates `owned_pending_entry_live_conflict` rather than generic
  `unpaired_live_position`.
- `owned_pending_entry_live_conflict` is now a live-artifact blocker in
  `V1RecoveryDecisionCore`, runtime entry gating, startup flat-truth release,
  and V1 lifecycle closure projection. It blocks all new risk, routes to
  flatten/block management, and clears only through fresh account flat plus
  open-order truth.
- Diagnose and production health list pending maker/hedge local fills, expected
  legs, live quantities/sides, open orders, owner, conflict reasons, and
  `next_action=owned_pending_entry_live_conflict_cleanup`.
