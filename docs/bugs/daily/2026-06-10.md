### Production Symptom

Post-deploy review showed no service crash and no current Local L2 mainline
blocker, but the deploy window still had several safety/diagnostic events:

- `runtime.quote_stale` from sidecar quote evidence just over the quote budget;
- low-volume `runtime.entry_blocked_ws_bbo_selection`;
- one `runtime.entry_blocked_post_only_bbo`;
- `runtime.snapshot_fallback_last_good` / `runtime.snapshot_degraded`;
- `l2_evidence.stale_rebuild_count=1` even though no
  `runtime.entry_blocked_local_l2_selection` recurrence existed.

### Root Cause

This is a CL-061 follow-up, not a rollback to Local L2. Production already uses
`entry_readiness_provider=ws_bbo_quote_lease`; the remaining gap was quote
evidence ownership and diagnosis vocabulary:

- candidate snapshot freshness still treated stale sidecar quotes as direct
  entry blockers even when the active provider had fresher WS BBO for the same
  venue and symbol;
- post-only BBO protection correctly blocked would-take maker prices, but did
  not first reprice from the same fresh WS BBO evidence;
- `diagnose_live.py` counted `runtime.snapshot_stale` and
  `runtime.snapshot_degraded` as Local L2 stale rebuild evidence.

V1 and exchange-doc semantics still require fail-closed behavior for new
opening risk when fresh BBO is unavailable. Bybit PostOnly orders may be
cancelled if they would execute immediately, and Hyperliquid documents
post-only / ALO price errors separately from quote-provider health. Therefore
the fix reduces false blockers and false Local L2 attribution without deleting
the entry safety gates.

### Fix

- Added a source-aware WS BBO entry quote resolver. Under
  `ws_bbo_quote_lease`, stale sidecar quote evidence is resolved only when the
  WS BBO cache has fresh valid BBO for the same venue/symbol. The runtime
  records `runtime.entry_quote_evidence_resolved_by_ws_bbo`, marks that quote
  metric as fresh WS BBO evidence, and keeps the candidate in the entry path.
- Sidecar missing/invalid quote remains fail-closed even if WS BBO has a fresh
  quote. If WS BBO evidence is missing, stale, invalid, or outside the
  quote-lease age budget, stale sidecar quote evidence also remains
  fail-closed through the existing quote-stale path.
- The WS BBO post-only guard now attempts one maker-side reprice when a fresh
  BBO proves the current maker price would cross. BUY reprices to best bid;
  SELL reprices to best ask. If the repriced price would still cross, or BBO
  evidence is missing/stale/invalid, the guard still emits
  `runtime.entry_blocked_post_only_bbo`.
- Dispatch writes the repriced maker hint back to the eventual order context and
  emits nonblocking `runtime.entry_post_only_bbo_repriced` evidence.
- `diagnose_live.py` now returns `snapshot_evidence` separately. Local L2
  evidence no longer counts snapshot stale/degraded events, and conclusion
  next-actions say "snapshot stale/degraded" instead of "L2 stale/rebuild" when
  there is no true Local L2 event.
