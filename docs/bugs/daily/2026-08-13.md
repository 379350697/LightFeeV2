# Bug Ledger Daily - 2026-08-13

## Cluster CL-103-ws-bbo-candidate-l2-final-cost-path

### Contract

The approved live flow is unchanged:

`manual coin list -> lightweight shortlist -> primary/shadow candidate L2
preparation -> true-L2 final cost reprice -> existing risk and order flow`.

WS-BBO remains the provider for entry quote readiness and passive-maker price
management. It must not replace the independent candidate L2 books needed by
the final two-leg VWAP, maker/taker fee, exit-cost, filtering, and re-ranking
calculation.

### Root Cause

`LiveRuntime._local_l2_effective_enabled()` correctly becomes false when
`entry_readiness_provider=ws_bbo_quote_lease`; its owner is the legacy global
L2 readiness/dispatch profile. Candidate-L2 activation and post-shortlist
snapshot synchronization incorrectly used the same predicate. As a result,
the BBO profile created no candidate L2 books while
`_reprice_final_l2_candidate()` still required both ready books and rejected
each finalist as `final_l2_unavailable`.

V1 keeps these concerns separate: after discovery it assigns/synchronizes
only promoted Local L2 candidates, then applies execution-liquidity costs and
the final gate. Its `entry_requires_hot_local_l2()` is based on the L2 strategy
contract, not on a quote-provider switch.

### Repair

The smallest separate predicate,
`_final_l2_candidate_data_enabled()`, is true when `local_l2_enabled` is
configured. It is used only for candidate-scoped L2 activation and the
post-shortlist sync. The existing `_local_l2_effective_enabled()` continues to
own BBO-vs-L2 entry readiness, passive maker behavior, startup activation, and
L2 state persistence.

This does not add a screening stage, auto-discover symbols, change the manual
coin list, or create a shadow-trading workflow. Candidate selection remains
limited to the existing primary/shadow scope and the final repricer remains
fail-closed on missing, stale, crossed, invalid, or insufficient-depth L2.

### Regression Coverage

- A real live tick with WS-BBO readiness activates only the selected two-leg
  candidate books, reprices from true L2, and reaches the existing executor.
- Direct candidate activation proves BBO leaves global L2 execution mode off
  while still creating the two required L2 books.
- Final reprice filtering/re-ranking and the legacy BBO startup-L2 diagnostic
  block remain covered.

### Operational Configuration: order quote age

Read-only cloud inspection found the running live service loads
`/opt/lightfee-v2/config/live.toml`, where
`runtime.max_order_quote_age_ms=10000`. Observed candidate/order quote ages of
12--14 seconds therefore hit the intentional stale-quote boundary.

The user-approved production setting is now **15,000 ms**. The tracked live
template is updated and the untracked production `config/live.toml` is changed
during deployment. This is a bounded tolerance change for the sidecar/order
quote freshness path only. It does **not** alter
`strategy.entry_quote_lease_ttl_ms=1500`, so WS-BBO entry-lease freshness stays
at 1.5 seconds; missing, invalid, and older-than-15-second sidecar quotes
remain fail-closed.

### Deployment Acceptance

Post-deploy verification must confirm all of the following from the live
process configuration and journal:

1. `max_order_quote_age_ms=15000` is loaded by the service.
2. `entry_quote_lease_ttl_ms=1500` remains unchanged.
3. BBO mode reports `local_l2_effective_enabled=false` and
   `final_l2_candidate_data_enabled=true`.
4. Candidate-scoped L2 events can occur, while legacy global L2 startup events
   remain absent.
5. No abnormal position, single-leg, pending entry/close, or new order-error
   artifact is introduced by the restart.
