### Production Symptom

The recent production fixes closed real issues, but their semantics were still
spread across several local decision sites: WS-BBO quote lease scope,
pending-entry terminality, passive-close live-flat resolution, residual dust
terminality, recovery block/clear, diagnose, and production health. That made a
future drift plausible even when every individual fix was correct: one path
could decide "flat", another could decide "clear", and a third could decide
"entry allowed" without all of them sharing the same V1 owner/evidence row.

### Root Cause

The code already had good V1-compatible pieces:

- `PendingEntryTerminalizer` for pending-entry terminal removal.
- `V1RecoveryDecisionCore` and `RecoveryLedger` for recovery truth.
- Residual dust rules that separate exchange-min dust from abnormal residuals.
- Passive-close terminal-flat paths that converge on exchange truth.
- WS-BBO primary+shadow scope fixes that keep execution-grade market data out
  of full-universe hot paths.

The remaining gap was architectural: runtime, diagnose, health, and event
surfaces could still independently reinterpret those facts. That is how fixes
become additive but not compositional.

### Source Truth

- V1 compatibility-sensitive trading semantics are authoritative for recovery,
  passive close, residual repair, pending terminality, and live-position truth.
- Exchange truth outranks local recovered state.
- Pending entry removal must pass through the terminalizer or equivalent
  terminal proof; live open order/live position/positive-fill evidence cannot be
  swallowed by local stale cleanup.
- Passive close/recovery/residual release must be tied to terminal exchange
  truth or explicitly tolerated exchange-min dust.
- WS-BBO effective entry quote lease may replace Local-L2 as the evidence
  source, but it must keep V1 primary+shadow tracked scope, freshness
  fail-closed behavior, post-only guard semantics, and close-price evidence
  boundaries.

### Fix

- Added pure `lightfee/engine/v1_lifecycle_closure.py`.
- The table emits rows for:
  `ENTRY_QUOTE_LEASE`, `PENDING_ENTRY`, `OPEN_POSITION`,
  `PASSIVE_CLOSE`, `RESIDUAL_REPAIR`, `RECOVERY_TRUTH`,
  `RUNTIME_PROGRESS`, and diagnostic-only event families.
- Every row carries `row_key`, `phase`, `owner_id`, `evidence_class`,
  `terminality`, `entry_policy`, `recovery_policy`, `diagnostic_severity`,
  `v1_anchor`, `input_hash`, and `closure_decision_id`.
- Runtime current-state export now writes `v1_lifecycle_closure`.
- Diagnose and production health render or rebuild the same closure payload
  instead of independently deriving V1 business semantics.
- Runtime entry recovery gate now reads `entry_gate_from_closure()` from
  `closure.summary`, not direct ad hoc recovery ledger conditions.
- Recovery block/clear journal events include closure row identity.
- Pending entry removal emits
  `pending_entry.removed_by_v1_lifecycle_closure` with
  `closure_decision_id`.
- Residual terminal and tolerated entry dust events include the same closure
  decision identity.
- Passive close normal terminal resolution, live-flat fallback terminal,
  position lifecycle terminal, and `recovery.flat` carry the passive-close
  closure identity captured before local state is popped.
- Closure building can reuse the runtime-owned `RecoveryLedger` and
  `V1RecoveryDecisionCore` result. This avoids a real potential drift where a
  second owner-unaware projection could misclassify an owned live order as an
  orphan.
- Row-level incremental reuse preserves `closure_decision_id` for unchanged
  rows.

### Non-Changes

- No order submit, order cancel, runtime-state mutation, strategy threshold,
  liquidity/OI filter, sizing, exchange credential, production config, WS-BBO
  budget/TTL, Local-L2 opt-in, close executor, residual repair submit, or
  recovery flatten policy changed.
- This is a semantic projection and gate/release adapter change, not a trading
  aggressiveness change.
- It does not claim mathematical "no漏洞"; the engineering contract is:
  no unmapped lifecycle events, no release path without a closure decision id,
  no entry/recovery gate bypassing the table, and no full-universe hot-path
  quote/freshness projection in WS-BBO effective mode.
