- Watch: `entry.opened` with `balanced_quantity=0`, `runtime.position_opened` with zero quantity, `runtime.risk_snapshot_fetch_error` containing `could not convert string to float`

### Summary

Current cloud run `lightfee-1779422875621-1388521` shows `open_position_count=2` but 7 exchanges report no real positions and no open orders. Two pending entries (`PROVEUSDT`, `XCNUSDT`) finalized with `maker_leg_filled=0.0` and `hedge_leg_filled=0.0`, producing ghost open positions. Additionally, Bybit risk snapshots fail with `could not convert string to float: ''` on `totalMaintenanceMargin`.

### Root Cause

**P0-A: Zero-fill finalize V1 parity drift — first fix was incomplete.**

First fix added `balanced_quantity <= 0` gate but unconditionally emitted `entry.passive_unfilled` and popped the pending entry for ALL zero-balanced cases, including `maker_leg_filled > 0 && hedge_leg_filled == 0` (real one-sided exposure). This silently removed pending entries with real fill evidence instead of routing them to fail-closed cleanup.

V1 (entry_sync.rs:2109-2127): `!pending.has_any_fill()` is the gate for zero-fill removal. When `has_any_fill() && balanced_quantity <= 0`, V1 enters `abort_pending_entry_fail_closed` rather than silently removing the pending entry.

**P0-B: Bybit risk snapshot test did not call real transport method.**

The helper `_bybit_snapshot_with_fields()` manually replicated the parsing logic in the test, so if the real `fetch_account_risk_snapshot()` broke, tests could still pass green.

**P0-C: `_parse_optional_float("NAN")` returned `float("nan")`, not `None`.**

V1 uses `eq_ignore_ascii_case("nan")` so all case variants ("nan", "NaN", "NAN", "Nan") must return `None`. Non-finite float values (`float("nan")`, `float("inf")`, `float("-inf")`) must also return `None`.

### Fix Status (Third revision — residual V1 parity)

Fixed locally, not deployed.

**P0-A (rev3):** `_finalize_pending_entry` now has full V1 `build_residual_task` parity (entry_sync.rs:5338-5454):

1. **Residual task computation before branching** (V1 line 5338-5341): `split_entry_fill_residual()` is called on the fill pair BEFORE the `balanced_quantity` branch, exactly matching V1's `pending.build_residual_task()`.

2. **`balanced_quantity > 0` with asymmetric fills** (V1 line 5423-5430): After creating the OpenPosition and emitting `entry.opened`, if a residual task exists (e.g. maker=10, hedge=8 → 8 balanced + 2 excess), it is persisted as `incremental_entry_open_partially_matched` in `state.pending_residual_repairs`. V2 was previously missing this residual branch entirely.

3. **`balanced_quantity == 0` with `has_any_fill()`** (V1 line 5436-5443): The one-sided residual (e.g. maker=10, hedge=0) is persisted as `incremental_entry_open_unmatched_residual` in `state.pending_residual_repairs`, no `entry.opened` is emitted, and the pending entry is terminalized without entering fail-closed by itself. V2 was previously calling `_abort_pending_entry_fail_closed` without creating a V1 residual task.

4. **`balanced_quantity == 0` with `!has_any_fill()`** (zero-fill): Unchanged — `entry.passive_unfilled` with safe removal.

5. **`_recover_residual_repairs` fixed**: Previously removed residuals whose `position_id` had no matching `open_position`, and an intermediate review found the fallback path could crash with `NameError: ResidualOrigin is not defined`. Now residual repair uses the V1 task contract (`repair_venue`, `repair_side`, `repair_quantity`) and queries the live venue position to compute only the excess over the matched baseline. It submits one reduce-only IOC repair leg for that excess, so partially matched positions are not full-closed.

**P0-B (rev2):** Unchanged — `TestBybitRiskSnapshotEmptyStringV1Parity` calls real `VenueTransport.fetch_account_risk_snapshot()`.

**P0-C (rev2):** Unchanged — `_parse_optional_float` uses `stripped.lower()` for case-insensitive comparison and `math.isfinite()`.

**P0-B (rev2):** `TestBybitRiskSnapshotEmptyStringV1Parity` now creates a real `VenueTransport(spec=bybit_spec(), mode="live", credential=...)`, mocks `_request()` to return Bybit `/v5/account/wallet-balance` shaped responses, and calls `await transport.fetch_account_risk_snapshot()`. Tests cover empty string, `--`, `null`, `n/a`, `nan`, `NAN`, valid number, and empty equity.

**P0-C (rev2):** `_parse_optional_float` now uses `stripped.lower()` for case-insensitive comparison: `"nan"`, `"inf"`, `"infinity"`, `"-inf"`, `"-infinity"`. Also rejects non-finite Python float values (`float("nan")`, `float("inf")`, `float("-inf")`) via `math.isfinite()`.

### Regression Watch

- `entry.opened` must never have `balanced_quantity=0` or `quantity=0`.
- `runtime.position_opened` must never be emitted for a zero-fill pending entry.
- `entry.passive_unfilled` must only be emitted when `not has_any_fill()` (zero-fill).
- `pending_entry.zero_balanced_with_fill_retained` must be emitted when `has_any_fill() && balanced_quantity <= 0`.
- Pending entries with real fill evidence must only be terminalized after a V1 residual task is persisted; they must not disappear as `passive_unfilled`.
- Bybit risk snapshot must never crash with `could not convert string to float: ''`.
- `_parse_optional_float("NAN")` must return `None`, not `float("nan")`.
- `_parse_optional_float(float("nan"))` must return `None`.
- `_parse_optional_float(float("inf"))` must return `None`.
- `_parse_optional_float("0")` must return `0.0` (not `None`).
- Partially matched entries (e.g. maker=10, hedge=8) must create `incremental_entry_open_partially_matched` residual task for the excess using V1 `repair_*` fields.
- One-sided unmatched entries (e.g. maker=10, hedge=0) must create `incremental_entry_open_unmatched_residual` residual task using V1 `repair_*` fields.
- `_recover_residual_repairs` must not drop unmatched residuals or full-close matched positions; it must query the repair venue and submit only the live excess as reduce-only.
- `split_entry_fill_residual` must be called BEFORE the `balanced_quantity` branch in `_finalize_pending_entry`, not inside it.
