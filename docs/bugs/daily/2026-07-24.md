# Bug Ledger - 2026-07-24

## Cluster CL-158 - OKX Prefixed Alias Reused One-Unit Contract Data

Status: local verified; production deployment verification pending.

### Symptom

OKX repeatedly appeared degraded for `BONKUSDT`, `FLOKIUSDT`, `PEPEUSDT`,
`SATSUSDT`, and `SHIBUSDT` even though the venue-wide market ticker request
continued to succeed. The sidecar retained market coverage for all 305 OKX
rows but funding coverage was 300/305; the five excluded rows had invalid
funding receipt/timestamp/interval fields.

### Evidence

- The global symbol universe contained both the bare and `1000`-prefixed
  canonical forms for each affected asset.
- OKX public responses accepted `BONK-USDT-SWAP` (and the equivalent four
  bare contracts) but returned application code `51001` for the corresponding
  `1000...-USDT-SWAP` identifiers.
- The live raw price for `BONK-USDT-SWAP` was approximately `0.000002889`,
  matching the bare `BONKUSDT` price unit, not the approximately `0.002882`
  `1000BONKUSDT` price unit used on other venues.
- The current `ctVal` values prove contract quantity conversion, not a price
  conversion. They cannot justify relabelling a one-unit ticker as a
  thousand-unit canonical symbol.

This is distinct from CL-084's cold-cache funding fan-out problem: the batch
funding request remained successful and the snapshot continued to publish.

### Root Cause

The May prefix-stripping compatibility change in
`MarketDataClient._fetch_okx_style`, targeted entry OI, and bulk BBO treated a
prefixed canonical symbol as a fallback candidate for the stripped OKX wire
symbol. When both canonical forms were present, the full funding path marked
the shared wire identity ambiguous and emitted invalid rows. When only the
prefixed form was present, the BBO path could instead attach the bare contract
price to the prefixed price unit, which could create a false spread.

V1's explicit venue-symbol mapping is authoritative per executable contract;
it does not license one OKX wire contract to serve two canonical price units.

### Root Fix

- Remove all `1000`/`1000000` prefix fallback mappings from OKX full funding,
  targeted OI, and bulk BBO acquisition.
- Preserve only exact canonical-to-wire mappings. A bare OKX contract therefore
  publishes only for the matching bare canonical symbol.
- Treat OKX application code `51001` as `symbol_not_listed`, not `http_error`.
  This keeps an absent prefixed alias from degrading otherwise healthy venue
  transport evidence.
- Continue to fail closed: a canonical whose exact OKX wire contract is absent
  receives no executable quote and cannot be used for a candidate or order.

### Verification

| Scope | Expected result |
|---|---|
| full funding with `1000BONKUSDT` and `BONKUSDT` | only `okx:BONKUSDT` is emitted; its funding and contract fields are usable |
| bulk BBO with only `1000BONKUSDT` | no quote is emitted; the bare contract is never relabelled |
| targeted entry OI with both names | bare contract is observed; prefixed alias is `symbol_not_listed` |
| production acceptance | no OKX alias-induced degraded symbols; no same-contract/self candidate; fresh rows retain exact wire and price units |
