## Cluster CL-001-passive-close-bybit-tick-v1-drift

### Summary

Cloud latest deploy was active but not effective for the current passive close. The run stayed in `risk_only` / `fail_closed` with an `ALTUSDT` open position and a pending passive close. The repeated blocker was:

`exit.passive_close_invalid_aligned_price`: Bybit maker short close, `price_hint ~= 0.0078`, `tick_size=0.01`, `aligned_price=0.0`.

Bybit public instruments info for `ALTUSDT` reports `priceFilter.tickSize=0.000001`. The local V2 path had the dynamic venue rule available at the transport layer, but passive-close pre-submit validation used the static `VenueSpec` / adapter tick first and failed before the transport order preflight could correct it.

### Review Finding

Self-review found the first local fix was incomplete. It added dynamic symbol-rule lookup before static tick, but still missed V1's second fallback: when passive order metadata is absent, infer tick size from quote precision (`best_bid`, `best_ask`) before any static fallback. That was a real V1 drift and would leave the close vulnerable if metadata fetch failed while local-L2 was hot.

Follow-up review found a second completeness gap: `SymbolRulesCache` returns `rule_source="spec_fallback"` when a venue has no dynamic fetch path or when the dynamic endpoint fails. Treating that as passive metadata would make the fix Bybit-shaped instead of V1-shaped. `_get_symbol_rule_tick_size()` now returns `0.0` for `spec_fallback`, forcing `_get_passive_tick_size()` to try quote inference before static tick for every venue.

### Shared Root Cause

V2 copied the passive price alignment behavior but not V1's passive tick source precedence.

V1 order:

1. `adapter.passive_order_metadata(symbol).tick_size`
2. infer price tick from quote best bid / best ask fractional precision
3. if needed, infer from target price distance / spread
4. otherwise no passive tick

V2 order before the fix:

1. static `VenueSpec.price_tick` or `adapter.price_tick_size`
2. align the passive close price
3. fail locally when static tick was larger than the sub-cent instrument price

The venue transport already knew how to fetch Bybit instrument metadata, but passive close blocked before submitting a request to that transport path.

### Fix Status

Fixed locally, not deployed.

- `_submit_maker_order()` and `_maintain_maker_order()` now call async `_get_passive_tick_size(..., target_price=price_hint, side=maker_side)`.
- `_get_passive_tick_size()` resolves true dynamic symbol-rule tick via `get_symbol_rules_cache()` before static tick.
- `_get_symbol_rule_tick_size()` ignores `rule_source="spec_fallback"` so static defaults cannot masquerade as V1 passive metadata.
- `_infer_passive_tick_from_l2_quote()` matches the V1 quote fallback by deriving fractional tick precision from hot local-L2 `best_bid` / `best_ask`, with distance/spread fallback for integer quotes.
- `_get_passive_tick_size()` now returns `0.0` when neither true metadata nor quote inference is available. The old static adapter/spec fallback was removed from the passive close path because V1 does not use it for `passive_order_tick_size()`.
- `LiveRuntime.start()` injects `_resolve_local_l2_quote()` into `PassiveCloseExecutor`.
- `LiveRuntime._resolve_local_l2_quote()` returns hot local-L2 top-of-book bid/ask for the passive close executor.
